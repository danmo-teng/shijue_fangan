# 智能救援完整比赛流程（独立程序）

本目录是独立于`rescue_map/`和`mission_test/`的完整比赛流程程序。旧的T265/编码器调试和旧任务测试程序保持不变；本程序复用同一套定位器、YOLO模型、相机分辨率、地图导入、融合权重和T265平移比例调试项。

## 启动

桌面安装：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/competition_rescue
./install_desktop_launcher.sh
```

随后双击桌面的“智能救援完整比赛流程”。也可以命令行启动：

```bash
./run_competition_map.sh
```

启动页仍可选择：

- 1～4号出发区、红方/蓝方；
- `T265+编码器`或`仅T265`；
- 编码器融合权重；
- T265预建地图导入/重定位；
- T265平移比例是否启用及`±0.01`调节。

默认开局策略是：离开出发区后保持开局观察和F407本地SEARCH扫描，直到识别到稳定物资；不再判断是否为单独绿色，也不会因等待时间经过而跳到正式搜索。稳定目标统一抓取并临时转移到靠近出发侧、避开中心—安全区通道的位置，再返回中心寻找首件正式投送的绿色物资。开局临时藏物资使用`initial_stash`审核，不按正式投送的类别和数量限制拒绝。

首件完成后：优先选择`0.85 m`内的普通/核心批次（1～3件）；附近没有合适物资而有伤员时选择最近的单个伤员；随后才考虑更远的物资。伤员只能单独1件，危险目标永不作为投送目标。目标按稳定track ID锁定，中心没有可行目标后复查临时物资点。

前方危险目标会触发换道。运动状态超过设定时间没有有效定位位移时，先发送下位机退让命令；仍无位移再发送旋转+横移脱困命令，达到最大尝试次数后安全停车。车体中心接近场地边缘且规划方向继续向外时，会先转向场地内部；已越界则立即安全停车。

首件搜索只有在新鲜视觉帧中确实看到绿色物资、但没有绿色物资可以安全单独取得时，才会先持续发送带`CLUSTER_TARGET`的`APPROACH_TARGET`靠近聚集区域；收到新鲜`mode=37`和本次ACK后才发送`DISPERSE_PILE`，并等待新鲜`mode=35`。非法夹内组合能判断异常侧时仍先单侧释放、`YIELD_BACKOFF`后复审；第一次无法判断左右归属时发送`RELEASE_BOTH`让F407完成整批放下和撞分，收到新鲜`mode=34`及本次ACK后清空旧批次，持续发送HOLD等待F407进入`mode=3`，再从新视觉帧重新选取撞散后的目标。

每次投送完成后的`RETURN_CENTER`都会持续发送到原点的剩余距离，距离进入小容差后仍发送`D=0`，直到收到新鲜`SEARCH`状态才开始下一轮。

## 运行记录

新程序在`rescue_map/runtime/`保存：

- `competition_detections.jsonl`：按`--detection-log-fps`采样保存YOLO检测、track ID、置信度、框和地面坐标；默认10 Hz，不改变识别频率；
- `competition_events.jsonl`：状态切换、批次锁定、危险换道、退让和脱困事件；
- `competition_diagnostics.json`：当前状态、位姿、F407状态、批次、左右爪审核和命令；
- 启动新会话时，上述文件会归档到`runtime/history/`的`*_competition`目录。

YOLO其它类别阈值继续使用当前`0.30`，`green_supply`在推理结果中单独要求置信度至少`0.50`。阈值通过不等于单帧即可抓取，任务状态机仍要求track稳定和夹内审核连续稳定。

## 夹内判断区域标定

需要调整“物块是否在爪内”的画面区域时，先单独运行：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/competition_rescue
./run_capture_roi_editor.sh
```

标定程序使用正式比赛相同的相机分辨率、JPU/VSE预处理、YOLO模型和识别阈值，但不会打开串口或向小车发送命令。鼠标左键依次添加多边形顶点，右键撤销最后一个点；`C`清空、`R`重新载入、`S`保存、`Q`或`Esc`退出。黄色框表示该物块检测框中心位于当前多边形内。

区域保存到`vision/config/capture_roi.json`。正式比赛程序启动时会自动读取该文件，并以检测框中心是否落入多边形作为夹内候选判断。未重新标定时，默认区域与原先“画面下方四分之三”的判断保持一致。

识别窗口默认使用`420×336`的小窗口，保持5:4比例并移动到屏幕右下角，不覆盖主地图；窗口只绘制必要的目标框，不再叠加状态、位姿、类别文字或调试面板。`F`可在运行时切换全屏/小窗口；`Esc`只取消全屏或记录为忽略，不会结束任务；`Q`才退出识别任务。关闭窗口后识别和任务线程仍继续运行，但会停止显示。

识别循环实际按`--vision-fps`限频，显示与推理解耦。JPU/GStreamer错误会先记录并让规划线程发送`PAUSE`冻结当前阶段，默认切换到软件JPEG解码重启一次；恢复后按当前状态重发合法的新SEQ命令。若仍失败，程序保持运行并持续锁存停车、周期性重试。所有摄像头错误、重启、GUI异常和最终退出原因会记录到`competition_events.jsonl`，包括异常堆栈。

## 当前下位机配合

新流程使用现有15字节`TYPE=0x18`传输，并在`protocol.py`中定义新增动作码：明确冻结阶段的PAUSE、目标靠近、SEARCH心跳HOLD、退让、旋转脱困、单爪/双爪释放、受控打散、换道和左右爪货物审核。F407尚未在本目录中修改；配合要求见`docs/f407_competition_flow_handoff.md`。
