# 智能救援完整比赛流程（独立程序）

本目录是独立于`rescue_map/`和`mission_test/`的完整比赛流程程序。旧的T265/编码器调试和旧任务测试程序保持不变；本程序复用同一套定位器、YOLO模型、相机分辨率、地图导入、融合权重和T265平移比例调试项。

## 启动

桌面安装：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/competition_rescue
./install_desktop_launcher.sh
```

随后双击桌面的“智能救援完整比赛流程”。也可以命令行启动：

```bash
./run_competition_map.sh
```

启动页仍可选择：

- 1～4号出发区、红方/蓝方；
- `T265+编码器`或`仅T265`；
- 编码器融合权重；
- T265预建地图导入/重定位；
- T265平移比例是否启用及`±0.01`调节。

默认开局策略是：离开出发区后保持开局观察和F407本地SEARCH扫描，直到识别到稳定物资；不再判断是否为单独绿色，也不会因等待时间经过而跳到正式搜索。稳定目标统一抓取并临时转移到靠近出发侧、避开中心—安全区通道的位置，再返回中心寻找首件正式投送的绿色物资。开局临时藏物资使用`initial_stash`审核，不按正式投送的类别和数量限制拒绝。

首件正式绿色完成前，夹内最终必须恰好1件绿色。首件完成后，夹内实际只要是1～3件普通、核心或普通核心混合物资就直接GRAB/NAV，不再要求与APPROACH前预测批次的数量和类别完全一致；伤员仍只能单独1件。合法审核会把实际类别、数量和目的地写回当前批次。

前方危险目标会触发换道。运动状态超过设定时间没有有效定位位移时，先发送下位机退让命令；仍无位移再发送旋转+横移脱困命令，达到最大尝试次数后安全停车。车体中心接近场地边缘且规划方向继续向外时，会先转向场地内部；已越界则立即安全停车。

首件阶段只要出现新鲜、置信度合格的绿色，就立即根据是否孤立二选一：孤立目标普通APPROACH，不孤立目标CLUSTER_APPROACH，不再等待`hits>=2`形成空档。F407完成125°水平对正后直接转到140°，新鲜`mode=21+CLAW_VISIBLE`一到，上位机立即停止APPROACH并记录frame floor，只使用之后的新夹爪帧。普通和聚集目标均须在合爪前取得连续3个不同`frame_sequence`的一致审核；签名只比较总数、实际类别数量及危险/未知/伤员混装标志，不受物体在左右ROI之间抖动影响。任何不一致帧都会重新开始连续3帧统计，不再保留旧合法命中。

第一件绿色尚未完成、140°ROI至少2件且包含绿色，并且左右任一侧都无法通过一次普通曲线直接留下恰好1件绿色时，本轮最多发送一次`DISPERSE_PILE|FIRST_GREEN_BUMP(bit5)`。F407固定执行后退0.10 m、Touch闭爪、前进0.20 m、后退0.10 m、双开；动作期间mode25，完成后直接mode3。上位机不等待mode35，确认ACK和新鲜mode3后清除旧批次、cluster、track和frame floor，用动作后的新帧重新找绿色。第一件绿色完成后永久禁用该标志。

普通带侧DISPERSE无论第一次还是mode35后的后续曲线都由F407使用固定15°保持；25°仅属于普通`RELEASE_LEFT/RIGHT`单侧释放。无侧12°观察只保留给完全没有可强制归侧候选的异常情况。

夹内审核只在STM新鲜、`CLAW_VISIBLE=1`且摄像头角度严格为140°时启用；SEARCH/APPROACH使用的全局`vision.cargo`不会直接进入夹内决策。伤员和核心物资使用“底部中心进入大ROI且框重叠比例至少60%”，其他类别保持80%。每次进入mode21、mode38、新鲜mode35或合爪后的新mode23都会重新记录frame floor，清除旧审核、旧选侧和旧动作缓存，只接受其后的140°专用ROI帧。合爪前审核只授权F407执行抓取；若实际审核含核心，F407先锁存航向按编码器前进50 mm再合爪。合爪后F407上报`mode=23 + GRIPPER_CLOSED + CLAW_VISIBLE`，上位机重新取得连续3帧审核，只有收到带`AUDIT_VALID(bit4)`的新鲜mode22后才按合爪后实际类别、数量和目的地锁存批次并开始NAV。

正式抓取完成后先导航到对应安全区半区靠近场地中心一侧围栏前`0.60 m`预备点；该距离以小车旋转中心为基准，红方预备点`y=+0.54 m`、蓝方`y=-0.54 m`。随后按红方`90°`或蓝方`270°`定位航向正对安全区；上位机始终发送9000/27000，不增加角度补偿。进入预备点容差后持续发送同一帧STAGE NAV `D=0`，等待F407新鲜mode10、DISTANCE_DONE、夹爪闭合、本次relay和ACK全部确认后才ALIGN。对正后才统计本方安全区；连续3个不同视觉帧识别成功后，取三帧框坐标中位数并冻结，本次物资区使用冻结框宽`1/3`处，伤员区使用`2/3`处，向F407发送一次有符号像素偏差完成视觉修正转向。冻结后不再用近距离残缺安全区框改变方向。5秒内未形成连续3帧时直接按定位正方向降级推进。ENTER阶段上位机发送`D=0`且不置`DISTANCE_VALID`，定位不再参与推进速度或终点判断；F407从600 mm预备点开始完全按本地编码器累计距离，到位停车、张爪并把摄像头转到120°，稳定后上报mode15。上位机从mode15之后的新视觉帧确认物资进入安全区，再发送TASK_COMPLETE。

投送完成后F407先本地后退`0.30 m`再进入mode17；上位机看到新鲜mode16或mode17后立即持续发送原有`RETURN_CENTER H/D`，不会用HOLD中断本地退出。距离进入中心小容差后仍发送`D=0`。收到新鲜mode3后先保持HOLD，等待摄像头到120°并取得返中完成后的新视觉帧，才允许下一轮APPROACH。

SEARCH按F407本地顺序先在120°旋转一圈，再在90°旋转一圈。任一阶段发现合法候选立即APPROACH；累计约720°仍无候选时，上位机进入RETURN_CENTER并持续发送到场地中心的完整H/D，不再永久HOLD。返中D=0且F407重新mode3后清零扫描累计，从120°新帧开始下一轮搜索。安全区短时漏检只沿用最近安全区框做过滤，不阻止正常目标建立。

## 运行记录

新程序在`rescue_map/runtime/`保存：

- `competition_detections.jsonl`：按`--detection-log-fps`采样保存YOLO检测、track ID、置信度、框和地面坐标；默认10 Hz，不改变识别频率；
- `competition_events.jsonl`：状态切换、批次锁定、危险换道、退让和脱困事件；
- `competition_diagnostics.json`：当前状态、位姿、F407状态、批次、左右爪审核和命令；
- 启动新会话时，上述文件会归档到`runtime/history/`的`*_competition`目录。

YOLO其它类别阈值继续使用当前`0.30`，`green_supply`在推理结果中单独要求置信度至少`0.50`。阈值通过不等于单帧即可抓取，任务状态机仍要求track稳定；普通及聚集/分离后的最终GRAB都要求2个新帧一致，无效审核的分侧决策保持1个新帧。

## 夹内判断区域标定

需要调整“物块是否在爪内”的画面区域时，先单独运行：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/competition_rescue
./run_capture_roi_editor.sh
```

标定程序使用正式比赛相同的相机分辨率、JPU/VSE预处理、YOLO模型和识别阈值，但不会打开串口或向小车发送命令。只需编辑大ROI：鼠标左键添加顶点、右键撤销，`C`清空、`R`重新载入、`S`保存、`Q`或`Esc`退出。左右爪ROI会从大ROI沿`x=640`自动无缝平分，不能单独画出间隙。黄色框表示已明确归属左右爪，紫色框表示已进入大ROI但左右不明。

区域保存到`vision/config/capture_roi.json`。普通物资只要底部中心位于140°专用大ROI且有效重叠至少80%，就必须计入`total_count`，核心物资仍要求全框进入大ROI。左右爪ROI严格共享`x=640`边界且覆盖完整大ROI；物体通过大ROI后，使用底部中心所在半区确定左右爪，不再要求整框80%进入单侧ROI。上位机本地审核还分别记录左右真实绿色数量，但这两个计数不进入UART。

强制分拣选侧为确定性策略：仅左侧有绿色保留左侧，仅右侧有绿色保留右侧；两侧都有绿色时保留绿色数量较少侧，数量相同保留左侧；两侧都没有绿色时保留左侧，只有左侧为空才保留右侧。只要overall ROI内存在可归侧物体就直接发送带`SIDE_VALID`的DISPERSE，保留右侧时增加`TARGET_RIGHT`。无侧12°观察只用于overall ROI内完全没有可强制归侧候选的异常帧。

识别窗口默认使用`420×336`的小窗口，保持5:4比例并移动到屏幕右下角，不覆盖主地图；窗口只绘制必要的目标框，不再叠加状态、位姿、类别文字或调试面板。`F`可在运行时切换全屏/小窗口；`Esc`只取消全屏或记录为忽略，不会结束任务；`Q`才退出识别任务。关闭窗口后识别和任务线程仍继续运行，但会停止显示。

识别循环实际按`--vision-fps`限频，显示与推理解耦。JPU/GStreamer错误会先记录并让规划线程发送`PAUSE`冻结当前阶段，默认切换到软件JPEG解码重启一次；恢复后按当前状态重发合法的新SEQ命令。若仍失败，程序保持运行并持续锁存停车、周期性重试。所有摄像头错误、重启、GUI异常和最终退出原因会记录到`competition_events.jsonl`，包括异常堆栈。

## 当前下位机配合

新流程使用现有15字节`TYPE=0x18`传输，并在`protocol.py`中定义新增动作码：明确冻结阶段的PAUSE、目标靠近、SEARCH心跳HOLD、退让、旋转脱困、单爪/双爪释放、受控打散、换道和左右爪货物审核。F407尚未在本目录中修改；配合要求见`docs/f407_competition_flow_handoff.md`。
