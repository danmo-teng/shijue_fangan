# 正式比赛四键操作

2026-11-06，RDK `806e056` 已实现以下操作。F405 `d6ae45c` 已实现匹配的蜂鸣器接口，用户报告烧录完成；设备实际身份未读回，声音未确认，不能把上位机报文写入成功当成已经响铃。

| 按键 | 待机 | 本轮准备/运行中 |
| --- | --- | --- |
| 1 短按 | 查询出发区，1～4声短音 | 只查询 |
| 1 长按约1秒 | 出发区1→2→3→4→1，每次按住只切一次 | 只查询，不改坐标 |
| 2 短按 | 查询安全区：红方1声长音，蓝方2声长音 | 只查询 |
| 2 长按约1秒 | 红/蓝切换一次 | 只查询，不改目的地 |
| 3 按下松开 | 开始本轮；完成现有定位和首帧识别准备后自动出发 | 不重复启动 |
| 4 按下 | 请求停止 | 立即走人工ABORT通路，取消未完成的启动，保留已有观察 |
| 4 持续约2秒 | 保留选区，回待机 | 停止并关闭本轮视觉/定位，回待机；之后3号开始新轮 |

选择保存在 `rescue_map/runtime/operator_selection.json`，下次恢复；显式命令行 `--zone/--side` 优先。按住开机不触发动作，多键同时按时4号优先。30ms消抖、长按计时只用于识别人类按键，不是反馈新鲜度检查。

## 启动与部署

原桌面“智能救援完整比赛流程”及 `competition_rescue/run_competition_map.sh` 默认启用四键。脚本 `competition_rescue/install_button_autostart.sh` 已安装当前用户桌面自动启动项 `~/.config/autostart/rdk-rescue-buttons.desktop`，登录桌面后只进入待机，不发启动CONFIG，不开T265/视觉。已只读确认本机LightDM配置为sunrise自动登录XFCE，当前桌面运行于Xorg :0。VNC客户端可以断开，不必关闭桌面服务；断电重启/无显示器启动的实际结果仍须确认。

无需图形窗口时，可从终端/SSH运行同一入口：

```bash
/home/sunrise/RDK_X5/shijue_fangan/competition_rescue/run_competition_map.sh --headless
```

先关闭已运行的正式入口；单实例锁阻止重复启动两个按键入口。`--no-gpio-buttons` 可显式使用原鼠标/键盘入口，不要与按键入口同时运行。这里没有新增另一套比赛算法。

按3号是一次启动授权，不需要准备后再按一次。当前仍是冷启动SDK/模型，故不承诺按下立即移动；本次只把旧CONFIG移到首个真实识别结果之后，避免模型还没准备好下位机已经自动出发。T265 USB启动失败及冷加载耗时仍是现有未决项，不声称这次已经修好。

自动启动项只在登录时执行，安装它不会启动当前已登录桌面的监听。2026-11-06首次“无反应”检查时没有按键/待机进程，但GPIO服务正常、四键输入可读。已打开原正式入口到待机，确认唯一UART和按键线程在运行，未启动SDK/视觉/比赛；无需为此重烧F405。若已进入待机，勿再重复打开另一入口。

## 资源与接口

- GPIO只读现有sysfs，按控制器label＋offset找四键，不改23脚临时供电，不重新export/unexport。底层接线/启动配置见 `RDK_X5_BUTTON_GPIO_HANDOFF_20261106.md`。
- 待机使用现有C++二进制的 `--operator-uart-only`，仅接收单次蜂鸣/人工ABORT请求，不创建SDK、不查询或订阅传感器、不发CONFIG。
- 按3号先结束并等待待机UART所有者退出，再启动正式C++唯一UART/SDK所有者。雷达/T265/轮速降级、外参、比例、任务配对保持原实现。
- GPIO读取和人工ABORT在独立线程，不依赖地图刷新。人工STOP同时写本轮令牌控制文件；C++收到人工ABORT后不再转发本轮CONFIG/任务命令，避免模型启动或旧命令覆盖人工停止。这只是当前人工停止，退出后新会话重建，不是传感器故障锁存。
- 视觉已打开时STOP后继续观察；尚未打开时取消启动。长按4号复用原会话收尾，保留原日志归档逻辑。
- 新增0x20蜂鸣请求由同一C++ UART串行发送；声音不要求ACK，不作为启动资格。下位机实现任务见 `F405_BUTTON_BEEPER_HANDOFF_20261106.md`，机器合同见 `../localization/tools/contracts/f405_operator_beep_v1.json`。旧0x1B已有其他用途，不能使用。
