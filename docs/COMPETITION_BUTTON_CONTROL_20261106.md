当前给操作者/F405同学阅读的纯文本说明见[RDK开机自启与按键说明](RDK_STARTUP_BUTTON_GUIDE_20261109.txt)，下载副本为`/home/sunrise/下载/RDK_开机自启与按键操作说明_20261109.txt`。下文保留原实现及当时检查范围，不将旧固件身份或旧“未下地”状态当当前事实。

2026-11-06，基于`11c7b6c`新增用户选择的整链预热。F405 `d6ae45c` 已实现匹配的蜂鸣器接口；最近四轮实际自报`d6ae45c4/dirty1`，用户已实按确认蜂鸣恢复。当前本轮待机检查结果见文末。

| 按键 | 待机 | 本轮准备/运行中 |
| --- | --- | --- |
| 1 短按 | 查询出发区，1～4声短音 | 只查询 |
| 1 长按约1秒 | 出发区1→2→3→4→1，每次按住只切一次 | 只查询，不改坐标 |
| 2 短按 | 查询安全区：红方1声长音，蓝方2声长音 | 只查询 |
| 2 长按约1秒 | 红/蓝切换一次 | 只查询，不改目的地 |
| 3 按下松开 | 绑定当前车位/朝向到所选正式起点并开始本轮；未热好时记录一次请求，准备完成后自动开始 | 不重复启动 |
| 4 按下 | 请求停止 | 立即走人工ABORT通路，取消未完成的启动，保留已有观察 |
| 4 持续约2秒 | 保留选区，重新预热 | 停止并关闭本轮视觉/定位，自动预热下一轮；之后3号开始新轮 |

选择保存在 `rescue_map/runtime/operator_selection.json`，下次恢复；显式命令行 `--zone/--side` 优先。按住开机不触发动作，多键同时按时4号优先。30ms消抖、长按计时只用于识别人类按键，不是反馈新鲜度检查。

## 启动与部署

原桌面“智能救援完整比赛流程”及 `competition_rescue/run_competition_map.sh` 默认启用四键和整链预热。已安装`~/.config/autostart/rdk-rescue-buttons.desktop`，登录桌面后提前启动唯一T265 SDK/UART、雷达和YOLO，持续耗电，但不发开赛CONFIG/任务或尚未绑定的正式场地位姿。LightDM已配置sunrise自动登录XFCE；VNC客户端可以断开。新预热版本的断电重启/无显示器启动仍待确认。

无需图形窗口时，可从终端/SSH运行同一入口：

```bash
/home/sunrise/RDK_X5/shijue_fangan/competition_rescue/run_competition_map.sh --headless
```

先关闭已运行的正式入口；单实例锁阻止重复启动两个按键入口。`--no-gpio-buttons` 可显式使用原鼠标/键盘入口，不要与按键入口同时运行。这里没有新增另一套比赛算法。

预热完成提示1声短音；失败提示3声长音并返回UART待机，不自动循环重试。界面分别显示T265 Pose、主yaw、视觉推理哪些已到。失败修复后按3会重新准备并保留这一次开赛请求；若只想重新预热，长按4。

按3号是一次启动授权，同轮不重开SDK、不重新加载模型；以当前热Pose/主yaw建立所选正式起点参考，然后沿用原3帧CONFIG（原间隔40ms）。若预热未完，不承诺按下即可移动。T265 USB固件上传0字节问题仍未修复；轮速/主yaw无真实数据时也不能冒称已准备好。仅一次本地参考生效匹配，不新增下位机握手或时间资格门。

自动启动项只在登录时执行，安装它不会启动当前已登录桌面的监听。2026-11-06首次“无反应”检查时没有按键/待机进程，但GPIO服务正常、四键输入可读。已打开原正式入口到待机，确认唯一UART和按键线程在运行，未启动SDK/视觉/比赛；用户随后确认实体按键发声恢复，无需为此重烧F405。若已进入待机，勿再重复打开另一入口。

## 资源与接口

- GPIO只读现有sysfs，按控制器label＋offset找四键，不改23脚临时供电，不重新export/unexport。底层接线/启动配置见 `RDK_X5_BUTTON_GPIO_HANDOFF_20261106.md`。
- 正常预热提前启动正式唯一UART/SDK拥有者；原`--operator-uart-only`只用于预热失败后的按键/声音待机及非预热旧路径。
- 按3时复用同一个SDK会话；动态层使用现有align把最新热Pose、主yaw绑定到所选正式起点并重建轮速参考。预热局部轨迹与正式输出分开，metadata保留预热选择及实际开赛选择，不改外参/比例/降级算法。
- GPIO读取和人工ABORT在独立线程，不依赖地图刷新。人工STOP同时写本轮令牌控制文件；C++收到人工ABORT后不再转发本轮CONFIG/任务命令，避免模型启动或旧命令覆盖人工停止。这只是当前人工停止，退出后新会话重建，不是传感器故障锁存。
- 视觉已打开时STOP后继续观察，未完成的开赛请求取消；长按4结束本会话后立即预热新会话。进程组收尾包括本入口启动的上传/推理子进程，避免残留占USB。第一帧CONFIG已经写出但尚未完成三帧时退出，也按已发车事实执行原停止流程。
- 新增0x20蜂鸣请求由同一C++ UART串行发送；声音不要求ACK，不作为启动资格。下位机实现任务见 `F405_BUTTON_BEEPER_HANDOFF_20261106.md`，机器合同见 `../localization/tools/contracts/f405_operator_beep_v1.json`。旧0x1B已有其他用途，不能使用。
