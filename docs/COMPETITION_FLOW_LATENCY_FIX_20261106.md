## 上位机修改

1. `competition_rescue/state_machine.py`：兼容名`stm.fresh`现在仅代表收到过可用状态，不按250ms阻断普通流程；
   新的明确名称`audit_fresh`仅保留合爪证据授权的原250ms检查。状态年龄继续显示。缺数据、实际模式/动作身份和人工STOP没有伪造。
2. `competition_rescue/run_competition_rescue.py`：当前接近动作的明确同任务REJECT先于context_pending处理，
   普通情况恢复SEARCH；已有分离预算/恢复任务时沿原RETURN_CENTER结束当前批次，避免与现有F405预算规则死锁。
   不把旧任务拒绝或已接受动作的重复拒绝当作当前取消。等普通像素接近ACCEPT期间继续更新目标和源画面；定距有限动作仍不重开。
3. `localization/src/main.cpp`：去掉命令续发250ms截断；最后真实命令持续到明确替换、人工STOP/ABORT或进程退出。
   两份逐Pose CSV改为`include/async_csv_log.hpp`有界后台写盘，行序/原时间保留；结束事件`diagnostic_csv_status`记录丢行/I/O错误。
   日志失败不决定控制是否运行。
4. `localization/tools/lidar_yaw_debug/worker.py`：独立接收子进程唯一打开雷达UART并连续解析；原运动工作进程持续消费Pose/轮速/yaw并发布状态；
   拟合线程消费最新完整扫描，有界待拟合槽覆盖旧请求，不再排四帧FIFO。原始字节和完整扫描仍保留，覆盖数有记录。
   无新年龄/时间资格门。断连仅暂停墙修正，原运动传播与既有端口重连保持。
5. `lidar_yaw_debug/dynamic.py`：原提线、单轴约束、双轴重获和源切换算法保留；昂贵提线不持有运动锁，
   算法应用前核对同一参考修订，显式重新绑起点/暂停雷达时撤销旧拟合，避免跨参考应用。
6. `competition_dynamic_localization.py`：Pose输入、底盘反馈转发和控制发布分开调度；不再先排空2048项底盘事件才读一次Pose/发布位姿。
7. `t265_wheel_input.py`及`debug_wheel_input.cpp`：同批已就绪速度只向SDK所有者发送最新一份，SDK端也合并积压请求。
   原始轮区间用于原运动积分并记录，合并计数与真实SDK调用分开；不按年龄拒绝、不伪零、不重放历史速度凑频率。
   B→C杆臂/旋转、SDK T=W=0、0.1m/s工程噪声、真实send_wheel_odometry调用及API结果保持。

新增模块日志仅`lidar_reader_events.jsonl`、`lidar_reader_summary.json`，已登记同模块白名单；本轮未运行日志清理。
底盘UART和T265 SDK各仍只有原C++所有者；未新增TYPE/opcode、订阅握手或外部位置加权。
