# 两侧搜索点轮换

基于a8d1242增量，用户批准两点(0,+0.30)/(0,-0.30)m轮换、绕侧面、发现可抓目标让位，以及保留失败上下文。本轮不改其他历史待办。

## 行为

轮换用于开局结束后的正式SEARCH；初始中心物堆检查、正在运输和已有载荷审核不因本轮修改换站。

- 正常开局进攻/投送后在己方点搜索。本站搜索额度用原720°，无合法目标后不再返中心：先移至较近的X=±0.50m侧通道，再沿通道跨到另一点Y，最后移回X=0。实际车头U在出发时冻结，不按平移H转头；到点容差5cm。若旧/关闭开局流程从中心开始且还未建立过搜索站，先去己方点。
- 下一轮无果反向轮换。完整到达新站才更新站点正负号/visit；途中发现目标而停车不算到站。路线略去已在容差内的中间点；本来已经位于目标点时只作原收尾交接，不绕一圈。
- 途中发现按原类别政策可抓的目标：原step13同action发D=0结束当前移动，收到原成对DONE后发原step12恢复搜索姿态，再按现有新图/正常搜索→接近→整爪审核/分离。没有直接合爪、没有把旧画面当抓取资格，没有增加STOP/ABORT或取消协议。若恢复视角后目标消失，继续正常观察；原站扫描额度与失败记录保留。
- 单次接近失败不会清掉本站累计SEARCH转角。累计仅在原SEARCH处理里复用yaw增量，不新增时钟/巡检；临时接近/恢复的旋转不算搜索角。连续失败打断扫描时，720°表示累计搜索额度，不保证两种相机角度各自完成整圈；不中断时仍沿原120°/105°扫描。

## 失败上下文

最近16项有界历史，按visit归属：目标ID、类别、原始SEARCH及末次目标框、各自车位/yaw/相机角度。正常恢复、放弃和分离失败转搜索前记录，不因选择另一个目标就删除。相同visit的原ID暂缓；ID改变时只在相机角度相同、观察yaw差≤5°、车位变化≤25cm时借原框关联，再复用原位置/面积连续性尺度。它们是图像关联范围，不是数据年龄门控。

只过滤VisionSnapshot.cargo搜索候选，不动capture_cargo、capture_audit或ROI计数。换站/一次正常投送返己方点后建立新visit，旧记录仍在历史但不再屏蔽，避免永久黑名单。视角大变/重新分配ID时不能保证识别同一个实体；不将像素框当场地物块坐标，也不宣称绝无错认；暂缓时原候选拒绝事件明确标为FAILED_TARGET_THIS_VISIT。
