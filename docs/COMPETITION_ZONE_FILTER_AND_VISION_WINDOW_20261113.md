# 双方安全区候选过滤与识别窗口置前

2026-11-13，基于661bdf7增量修改。用户要求检查/排除对方安全区内部目标，
并在正式定位窗口加入一键调出识别画面的按钮。

## 安全区过滤

此前主循环只为本方选择一个最大色框，再传给tracked_cargo；搜索/接近的inside_safe_zone未覆盖对方。
run_competition_rescue.py现保留本方框用于对准/过道/投送确认，
另从当前检测结果取全部safe_red/safe_blue框，用于候选的任一安全区成员判定。
同色多框也全部参与排除，不只看最大框；所有目标类别沿用原规则：

- 框底边中点在安全区框内，且绿色/伤员/危险物框重叠比例>80%；黑色仍要求完整包含。
- 被判任一安全区内部的物块沿原_visible_cargo过滤，搜索、普通/聚堆接近不选它们。
- 区内蓝色也不作为场外接近危险物，避免不取它却继续按它触发前方危险反应。
- delivery_target_inside/outside仍从独立的本方成员结果计算，不能把对方区内物块计作己方投送成功。
- 爪内审核继续使用完整人工ROI，不把已经夹住、投影在安全区色框上的载荷从审核中删除；P0全量类别/数量保留。

本轮未调整面积/脚点阈值，未新增地图禁区、帧等待、时间门或动作中断/握手。
仍依赖当前画面实际检出的安全区框；未检出或遮挡的真实边界不能凭空推断。
既有在途动作、目标恢复、整爪审核和分离流程保持原语义，不把候选过滤说成物理禁入保证。

## 定位窗口“识别窗口”按钮

competition_map_app.py右上角改为四按钮：最小化、窗口/全屏、识别窗口、退出，选区和比赛中均可用。
“识别窗口”按既有精确窗口名complete_rescue_competition恢复、抬高并激活识别窗口；
复用已安装xdotool，不用同步等待窗口出现，不重启/另开YOLO、摄像头、SDK或底盘拥有者。
未打开/已关闭时只在地图消息中提示，不影响比赛运行；此操作为点击时置前，不新增后台反复抢焦点。

## 实际验证

6项相关软件检查通过：

- 红/蓝方、双方及同色多框全部排除；场外目标保留，脚点在前沿外的高重叠物不误判为内部。
- 所有可见物块都位于任一安全区时保持搜索，不产生接近/抓取目标；已锁定的区内物块不作为接近取点。
- 本方色框仅缓存/缺失时，对方当前真实色框仍可用于候选过滤。
- 对方物块不能确认己方投送；已夹蓝绿仍完整计入审核。
- 原区内外边界、两件投送确认、单锚点整爪审核、固定模板双角度矩形均保持。

实际X11桌面以唯一命名的静态测试窗核对：四按钮文字/命中框在选区和比赛两种布局无重叠；
识别窗最小化后，被普通或全屏窗口覆盖，两次点击均恢复并成为活动窗口；
关闭后点击仅提示且不另启进程。测试结束关闭所建窗口，恢复原活动窗口。
没有使用真实摄像头、SDK、UART或启动车轮；未重启正式比赛，实际运行下次启动加载。

本轮无下位协议/代码/烧录需求。原ROI/模型/定位、其他未提交成果、原始日志均保留。
新绕行/清障和其他待办未实施。
