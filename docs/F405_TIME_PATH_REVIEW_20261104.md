# F405时间链审查与下一步讨论

2026-11-04。协作流程已获用户认可，具体固件改法仍在讨论，**本文件不是实施授权**。
本轮仅查源码、历史需求和已有日志，没有改运行代码、烧录、测中断耗时或启动车辆。

## 先给结论

- 正常收到的真实反馈应按用户已确认的工程策略采用；时间诊断不应成为层层许可。
  速度计算和gyro配对需要基本采样区间，跟“先证明所有时间误差界才准用”是两种不同用途。
- 可以直接精简纯诊断和纯年龄拒绝，不需要先把复杂质量系统修到完善。
- 不能保证一次修复消除所有FAULT。确定的时间快照竞态可以修；UART真实错误是否同时存在还没有证据定论。
- 整包删除timed功能不是可靠捷径：会丢掉已接通的实测07/08，且旧IMU恢复/停车链与竞态仍在。

## 哪些后来增加，哪些原本就有

对比14157e6→11eeacf（7个提交），其中cd26448引入timed反馈，43fa6ab修UART恢复，512038d增加质量证据/串行DMA所有权处理。
GitHub main本轮读回仍为11eeacf；问题会话板端actual=11eeacf/source_dirty=1。源码审查不等于实际镜像逐字节证明。

| 内容 | 来源/作用 | 当前建议 |
|---|---|---|
| 07真实轮速度、原始计数、t0/t1；08真实gyro/源序号 | timed新增；给官方轮速输入提供实际测量和区间配对 | 保留最小数据通路，不能回退成目标速度或按RDK到包间隔瞎算 |
| TIM5微秒计数、boot/reference标识、SYNC、固件身份 | timed新增；提供时间/来源记录 | 基本计数和来源可保留；不能把未知误差界当作不准用数据的理由 |
| 时钟寄存器健康巡检、漂移/采样误差质量页、逐沿耗时和大量延迟统计 | 后续新增诊断；原先服务严格质量资格要求 | 可关闭/移出高频路径/只按需运行；未测仍写未知，不伪装成0误差 |
| 8ms排队过期、20ms gyro陈旧标志并清VALID、轮间隔/时钟异常使反馈无效 | 新增时间门，仍可能在下位机就丢弃或废掉测量 | 按当前策略审查撤销纯时间拒绝，RDK同步取消对应不必要依赖 |
| CRC、合法字段、真实测量来源、DMA单一发送者与缓冲区生命周期 | 数据正确性/实际传输问题相关，不全是时间诊断 | 保留必要部分；去诊断不能回退已修过的串口所有权问题 |
| IMU的150ms失流/RECOVERING、Location无效、Debug及motor停车分支 | **14157e6已经存在**，不是这轮timed新增 | 另行明确控制行为；删timed模块不会自动清除它们 |

此前RDK任务还要求不确定度≤5ms、到SDK年龄≤50ms、gyro间隔≤20ms、漂移/边沿/模块滤波延时界。
这些是当时严格时间资格方案的要求，不是send_wheel_odometry逐样本API强制要求；用户后来已撤销其准入作用。
原始历史说明保留用于追溯，不得再次作为下位机必须完成的任务。

## 实际增加了什么中断工作

- IMU UART5：每个接收字节调用DebugTelemetry_NowUs；该函数关中断读取64位时间并做回退检查。
  合法角度/角速度帧完成后还更新遥测源快照和最大接收间隔统计。原1kHz模块/按字节接收方式早已存在，新增的是附加工作。
- 后轮EXTI：每个边沿前后各读一次微秒时间，再更新次数/最长耗时。
- TIM6的10ms路径：轮计数快照增加时间/挂起检查；WheelSample还累计区间、检查质量、做浮点速度换算和时钟健康检查。
  这些工作即使未订阅07/08，也不都消失，因为采样钩子只检查initialized，不检查streaming。
- UART4完成回调：关中断期间计算两次整包RAM指纹、读取源时刻、更新传输/年龄统计。
  DMA本身减少了逐字节发送中断，单一DMA所有权修复应保留；附加统计和诊断性重复检查应分别审查。
- **TIM5是1MHz硬件自由计数，不是每微秒一次中断。** 32位溢出约4294.97秒/71.58分钟一次，不能把它说成每秒一百万次中断。

目前没有可靠的板上CPU占用、最长关中断或UART5溢出因果测量，不能把上述静态审查说成“已经证明中断被这些代码拖垮”。
已有下位机VALIDATION文件也明确physical_timing_verified=false、board_verified_this_run=false。
该模块由`APP_BOARD_F405_ROBO && APP_ENABLE_MOTION_DEBUG_TASK`启用；NormalDebug和NormalDebugTimed均包含，
并非单纯改回115200或取消订阅就全部关闭。完整任务模式的新增timed钩子不启用，但共享旧IMU/电机逻辑仍须分开审查。

## 之前方案的具体问题

1. 把“有真实数据和可计算区间”与“时间质量必须获得证明”绑得太紧，给上机验证设置了超出必要程度的前置条件。
2. 用户撤销时间门后，清理未贯穿两端：下位机仍有过期丢包/清VALID，RDK仍依赖某些源有效位与时钟资格。
3. 诊断侵入高频路径，数据发布、质量统计和控制可用性耦合；停止订阅也不一定撤掉采样侧成本。
4. 上次建议加新诊断字段过早：程序器现有`IMU`命令已有RX_ERRORS、CRC_ERRORS、GAPS和RECOVERY COUNT，第一轮应先复用。
5. 只改Debug层FAULT会遗漏底层：Motor_Update、定距、定角、方向运动等也直接读取同一个IMU ready状态并停车。
   这是必须先审完整调用链的具体例子，不能让对方收到一条“删if”就动手。

还有同类新增竞态：DebugTelemetry_Process先取now，publish_gyro随后拷贝可能被ISR更新的样本；
gyro_flags执行无符号now-received时可能下溢成巨大年龄并清VALID。它可能影响注入，但不能冒充本次ODOM3的已证实直接原因。

## 下一版建议范围：供双方和用户选择

建议保留实测07/08及必要时间/身份，不重写PID、不改运动学、不扩诊断协议。优先：

- 修IMU_Update和遥测快照里已经看见的时间一致性问题；这是共享驱动修复，需说明对其他构建的影响。
- 去掉后轮逐沿耗时统计；IMU取时尽量只在完整合法帧完成处进行一次，不对每个字节追加计时。
- 撤掉纯时间资格清VALID/8ms过期丢包等门，保留数值、来源和物理通信完整性；不能把缺数据补成零或重复旧样本充频率。
- 高频时钟巡检、DMA回调内的诊断性指纹/年龄统计减掉或延后；保留单一发送者、稳定DMA缓冲区和必要故障恢复。
  轮速度计算是否移出TIM6，需要接收方先说明一致快照和对控制时序的影响，不在这份提案里盲目指定新队列/架构。
- RDK一起检查兼容依赖，尤其不能因质量查询能力关闭或时钟诊断不合格，再拒绝本来可用的动作/真实测量。
  字段布局尽量保持，具体语义变化须如实记录并审查，不能悄悄假报资格通过。

控制行为有两种真实取舍，仍需人决定：

| 方案 | 能解决什么 | 代价/未解决项 |
|---|---|---|
| A：上述修复/精简，先保留原IMU异常后的动作处理 | 范围较小，能验证明确软件问题及去除诊断成本 | 若真实UART错误仍使ready下降，动作仍可能被原有多层逻辑终止，不能保证一次治好 |
| B：同版再拆开“暂时接收/时间诊断”与“已有合法测量可用”，避免短暂恢复立即结束动作 | 更符合调试/比赛不中断的目标；保留动作身份和进度，等新合法帧更新，不自动重放 | 必须统一审查IMU/Location/Debug/motor各层；真实长期失去反馈时使用旧航向会失准，处置须人明确，不能暗中新增年龄门或伪造反馈 |

倾向讨论B，但不能只说“删除所有报错停车”。需要下位机负责人先用人能理解的方式说明：
正常样本、坏帧、尚无任何样本、短暂RECOVERING、真实持续无反馈时分别发生什么，哪些情况保留动作，哪些仍终止。
这是行为讨论，不要求新增一个复杂故障框架。人工STOP保持有效；真实执行器故障与动作自身超时不在本提案里顺手删除。

## 一次能否修好、如果不行怎么做

确定的竞态可以一次改掉，但日志缺少UART5错误计数，不能保证实际故障只有这一个原因。
第一轮不加新诊断：用现有程序器IMU输出对比RX_ERRORS与恢复计数，编译后做最短静止检查和用户授权的一段动作。
若仍出问题，按这个对照决定修串口错误还是再精简相关钩子；不继续叠加整套时间质量功能或测试框架。
纯诊断功能可直接去掉，不必“修到完善再删”；实测数据、必要计算时间和DMA生命周期不能无区分整包删掉。
