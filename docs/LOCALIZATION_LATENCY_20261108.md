- `worker.py`每次实际运动/参考/可观测修正变化后发布小控制快照；显示仍20Hz。
  不产生定时重复旧端点；新墙约束/参考/来源等可更新同一测量时刻，不能据此算新增传感器帧。
- `latest_snapshot.py`的MotionInbox用有界非阻塞本地数据报，去掉multiprocessing.Queue后台转发线程。
  单次数据报为一个完整内部消息，满时报告原input_drops；没有年龄门或“时间质量未知”准入。
  控制使用64KiB单槽共享内存和事件唤醒，未读取的旧快照合并并计数，不堆积补发。
- `competition_dynamic_localization.py`立即接收控制并送原C++动态位姿入口；完整显示状态由另一低频线程处理。
  按3起点绑定/退出有本地唤醒，不制造Pose、不增加MCU握手。新参考不叠画上一轮雷达点。
  C++动态入口原已可读事件驱动并直接发0x16，本步不改其协议、唯一UART/SDK所有权或任务配对。
- `dynamic.py`只复制扫描插值所需历史窗口，4096行原历史仍保留。
  最新支持端点用同一旋转/平移公式直接计算，避免构建数组/插值器和复制显示点；完整/控制位姿数值相同。
- `low_latency_scheduling.py`默认对输入、运动传播、控制发送线程用SCHED_FIFO优先级10。
  拟合、接收子进程、日志及GUI仍普通调度；创建后台线程/进程在提高本线程优先级之前。
  只在启动时用现有sudo权限给自己的进程/子进程设置rtprio限制，应用仍以sunrise运行。
  权限失败只记录实际策略并继续普通调度；`RDK_LOCALIZATION_RT=0`可做普通调度对照。
  没改系统内核、全局RT预算、登录配置、CPU频率或内核中断；不是新一套实时诊断框架。
