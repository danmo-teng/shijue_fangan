### 几何热点：相同算法与输出

原1秒扫描×3剖析：extract_lines占约92.4%拟合时间，主要是160候选N×H距离临时数组、百分位、TLS。C ABI流式评分保留相同160组候选、严格阈值、第一最大值规则；总时间复杂度仍O(NH)，中间存储从O(NH)降为O(N)，不改变墙面算法。ctypes.CDLL在数值循环释放GIL，缺库自动回原NumPy，不阻断定位。

保留两次TLS/SVD及分组；组内投影已经排序，5/95分位按NumPy相同线性插值直接读相邻元素，免再次拷贝/partition。固定主yaw的XY IRLS正规方程本来是对角矩阵，改成两个轴的归约求解，取消每次重复旋转与通用lstsq；观测轴、墙关联、门限和围栏重获完全保留。

原始10秒98个扫描离线对照：旧NumPy提线中位18.799/P9520.699/max23.524ms，新内核中位6.816/P959.637/max10.865ms。每扫描提取条数、支持点、法向、跨度逐项完全相同；另15组不同yaw/单双墙的新旧XY解最大差2.22e-16m。它是软件等价及计算收益，不是地面精度。

持续联合回放1000区间/10秒检查另列后续结果，不能以孤立提线倍数宣称端到端倍数。已试工作进程GIL 5→1ms：ABBA四轮1000区间均处理、输入/发送丢弃0，控制943/976/937/946端点，P9513.71/12.75/14.47/13.34ms；1ms一轮max55.70ms，没有稳定尾延迟收益，**未采用**。保留默认5ms，不靠试到最好的一轮报喜。当前还未达稳定每10ms交付。

## LATENCY-03本步：历史时刻修正

代码证据：`DynamicFence.observe()`在拟合外复制运动先验，拟合期间实际迟到Pose可修订运动历史最新端点。
旧代码把围栏给出的扫描时刻位置减去拟合前的先验，导致历史修订被再次带到最终位置。
离线复现：冻结先验X=0.010m，迟到Pose更新后同一时刻X=0.050m，已知模拟围栏后验仍为0.010m；
旧结果仍0.050m，残留0.040m。这是代码应用错误复现，围栏位置是夹具给定值，非独立实车测量。

`dynamic.py`改为在应用结果的原锁内，按**扫描reference_ns**从当前运动历史插值，
只在实际可观测轴上设置`offset = wall_position - current_motion_at_scan`，保留扫描之后的真实传播。
显示点也使用该平移基准；原10Hz扫描结果增加`applied_motion_reference_xy_m`和`motion_reference_update_m`，
仅记录已有计算，不新增高频计时/年龄检测或准入。协议、控制位姿字段、几何提线和来源策略不变。
这一步没有重算扫描内部的去畸变轨迹；运动先验本身有误、采样时刻映射误差仍会影响雷达结果。

现有`test_f407_motion_protocol.py`增加一个针对性检查，覆盖0/0.7rad场地旋转、XY/X单轴、
拟合时迟到Pose及扫描后100ms真实格式轮反馈：观测轴扫描位置误差低于1e-10m，
未观测轴不改，后续位移和真实端点时间保留。原动态补偿、来源切换和围栏重获相关检查通过。
复现派生文件`/tmp/rdk_latency_stage3_history_repro_20261108.json`，原始运行日志未改。

同代码的另一次1秒联合负载记录`/tmp/rdk_latency_stage3_joint_20261108.json`：

| T265会不会被错误轮速强制带走？ | Intel的Phillip Schmidt说明视觉/IMU可抵消轮速造成的位置偏差，调小测量协方差会增加轮速影响。说明估计同时利用多路信息；没有给出“打滑一定自动识别并降权”的保证。公开资料未披露其具体自适应/鲁棒策略，不能断言完全没有，也不能把它当可靠防滑开关。 |
| 停送轮速是否等于停止定位？ | 官方主机发送函数仅发一个速度观测包；官方ROS独立订阅回调收到消息才调用，不用轮速消息驱动Pose发布，也没有输入中断就stop的逻辑。据接口设计推断，仅不再调用send而保持pipeline运行，视觉/IMU Pose应继续；未对本机固件的停送过渡作实测保证。 |

| 能否动态改每样本协方差？ | 该API只有sensor_id、frame_num和三维速度；无每样本时间戳/协方差/融合权重或逐样本设备融合回执。配置的noise_variance是启动参数；本工程0.1m/s标准差对应0.01(m/s)^2，仍是工程初值，本步不调参或运行中重载配置。 |
| 延迟为什么仍应先优化？ | 官方v2.50发送函数让固件在收到包时填写两个时间戳；frame_num不是采样时间。旧速度集中补发无法依靠该接口附带原时间纠正。本轮事件链优化有意义，但上述夹具还未测出真实SDK响应延迟。 |
