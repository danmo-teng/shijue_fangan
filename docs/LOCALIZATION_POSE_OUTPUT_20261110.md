# POSE-OUTPUT-01：移出Pose消费线程的快照与终端写入

2026-11-10，基于`codex/gamepad-teleop@a9ddcd5`增量修改。用户要求按项交付、每项有意义且可检验，本项只处理已定位的输出阻塞范围。

## 问题与改法

前次原始日志分析发现九个SDK会话119次超过100ms的Pose消费间隙，全部紧接20Hz输出；测试路径未传`--dynamic-pose-socket`时仍同步写JSON，`POSE`文本也在Pose线程输出。这能定位阻塞范围，尚不能证明119次都由同一个文件操作造成。

`localization/src/main.cpp`现在对所有入口使用现有`AsyncLatestFile`写原始快照，去掉同步回退；JSON格式化也在后台进行。每次提交按值保存本帧数据及当时的`timestamp_monotonic_ns`，后台不能读取下一帧的可变状态，也不把实际写盘时间冒充Pose时间。

`POSE`文本使用同一现有机制的独立实例，格式化和输出均在其写线程。两个输出端各最多有一个正在处理、一个待处理的快照；慢终端不会占住JSON队列，过载只合并待写快照，不积压后补发。增加一个文本写线程，不新增进程或通用调度框架。

SDK读取、官方轮速注入、原始CSV、定位公式、安装参数、比例、来源切换、UART控制和比赛状态机均不变。正式动态JSON仍由原`DynamicPoseRelay`发布。本项共同修改的只是SDK主程序低频诊断输出，不把它说成正式雷达算法优化。

## 文件与接口

- `localization/src/main.cpp`：上述后台输出；关闭时收尾最新快照，沿用既有写出器行为。
- `localization/tests/test_omni_localization.cpp`：扩展既有慢写出检查，覆盖持续提交、不可变快照和两个输出端独立推进，未创建新测试入口。
- CLI、JSON schema 3和所有原字段、`POSE`文本内容、底盘协议均不变。原`diagnostic_csv_status`只追加`pose_stdout_write_errors`和`pose_stdout_coalesced`计数，无新增高频计时或运行门控。
- 写盘失败由既有后台错误计数报告，测试不再因同步JSON写出异常退出。原地图收尾仍通过`raw_json_write_errors`识别日志不完整；快照合并不等于逐帧原始日志丢失。
- 无F405配套修改。
