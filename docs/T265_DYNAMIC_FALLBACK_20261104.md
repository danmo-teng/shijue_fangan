# 动态测试定位来源切换与恢复

2026-11-04；基于499cf08增量实现。用户本轮选择“实测轮速＋主yaw＋雷达降级”。
仅原“雷达-T265动态定位”测试入口生效，未改正式比赛、F405、T265安装参数/比例或官方SDK输入定义。
本轮没有启动真实UART、SDK、电机或USB恢复；保留所有原始日志，不执行清理。

## 运行行为

- 正常：以T265车中心位置作锚点。Pose尚未覆盖的新区间，用已经收到的实测轮反馈续推，来源明确标为`T265_WITH_WHEEL_TAIL`。
  这段轮式位移从锚点的记录采样时刻之后开始；不重复累加锚点之前的位移，不对两套位置加权。
- 发现同区间空间矛盾或收到SDK失跟标志：进入`WHEEL_FALLBACK`，从最后采用的位置继续按实测轮速＋主yaw传播。
  原始T265继续接收/记录/显示，不改变SDK估计器，不停注入、不发送STOP，不形成底盘故障锁存。
- 两种来源都使用同一雷达围栏约束，只更新可观测X/Y轴。单墙继承另一轴；人工“越障暂停雷达”仍有效。
- 恢复：实际移动的区间位移重新一致，并连续获得双轴墙约束后，将T265平移参考对齐到当前传播位置，再切回。
  不修改安装旋转、不换90°场地分支；静止confidence升到3本身不能触发恢复。人工重新初始化仍沿用原按钮。
- 没有新的运动测量支持时，边界位置/航向保持在已有样本端点，明确记录`hold_outside_measured_support`。
  不再把最后两个SLAM位置之差无限外推；这不是生成新的零速度测量，也没有按年龄拒收真实数据。

界面增加缓存的中文来源标签“降级：轮速＋主yaw”/“T265定位／轮反馈续推”。
蓝线始终为原T265车中心，橙线为当前选定来源＋雷达修正；降级时不会偷偷用轮式轨迹替换蓝线。

## 数据与数学接口

复用唯一`ChassisTestClient`已有07/08反馈，经`TimedMeasurements.wheel()`验证当前F405计数公式后，
在既有后台反馈线程将`wheel`消息送到原雷达工作进程。没有第二个UART/SDK拥有者，没有下位机修改需求。
输入是`source=measured_wheel_feedback`的真实`v_body_mps`，不用目标速度、命令距离、T265速度或C点速度。

轮速度按原MCU区间`t0_us/t1_us`积分，主yaw保持逆时针正。在同一MCU时间轴上取区间两端主yaw并用中间角旋转速度。
若边缘缺少包围样本，使用最近的真实端点朝向并标记`MCU_interval_endpoint_held`；不伪报精确对时。
SDK/轮反馈的host映射仍是估计。没有映射时以接收区间末端＋原MCU区间长度定位，并记录来源；未硬改任何qualified字段。

轮式原生累计位移经`yaw_offset − vio_rotation`旋转到原T265局部坐标，再经过既有场地参考转换。
T265的定位中心→车中心补偿已经在上游完成，本模块不再补杆臂，不涉及内部IMU偏移。
雷达平移修正仍在传播历史之外应用，不把当前扫描反馈进自身去畸变。
SDK内已有轮速/主gyro依赖，因此本模块的位移比较只是来源一致性检查，**不是独立真值或独立观测融合**。

新增纯计算模块`localization/tools/lidar_yaw_debug/motion_source.py`；
`dynamic.py`负责选定历史与原始T265历史分开、边界保持和墙约束；
`worker.py`增加轮反馈接收和来源变更事件；`lidar_t265_motion_map.py`连接既有客户端并显示来源。
正式C++比赛通信、状态机、SDK外参T/W=0、pose jumping及比例1.000均未变化。

## 初始阈值及含义

这些是本轮正常/异常记录对照后的工程初值，不是标定精度，不作为长期固定参数约束。

| 判断 | 当前初值 | 作用 |
| --- | ---: | --- |
| 相邻已配对区间的T265/轮式增量差 | 0.05m | 捕获米级跳变，不限制接收到的数据年龄 |
| 比较段净位移差 | 0.05m | 捕获逐渐缩短/漂移 |
| 正常比较段实测轮行程 | 0.25m | 一致时更新比较起点，避免无限累积正常尺度小差异 |
| 恢复比较段位移差 | ≤0.025m | 比降级阈值严格，避免反复切换 |
| 恢复所需一致实测行程 | ≥0.50m | 需要真实运动支持，不靠静止confidence自证 |
| 恢复所需连续双轴墙约束 | ≥2帧 | 单墙/越障暂停/无墙不能授权完整XY恢复 |

计数、队列和日志均有界。缺少轮反馈时不凭空生成轮式位移，仍显示暂无轮参考；降级不能解决所有传感器同时缺失。
真实轮打滑、主yaw错误、墙误关联仍可能造成错误，必须用地面真值验证。
