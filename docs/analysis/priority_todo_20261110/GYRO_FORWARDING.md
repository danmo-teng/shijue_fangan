详见[逐会话统计、方法和原文件SHA](gyro_forwarding_review_20261110.json)。F/A/动态实际固件为ac61480/dirty1，正式为9434608/dirty1；此次审查的b56bc80不是这些日志的实跑版本。

这些数值是**每次100Hz发布选中最新源的快照等待**，不是所有1000Hz原包逐一转发的延迟。pub时刻在构帧入队之前，尚不包含入队→DMA起发、最后字节上线、RDK收包及消费；当前日志没有DMA起发时刻，不能据0.94ms声称全链小于1ms。约1000Hz接收、100Hz选最新源和控制频率也不能混为一个频率。

此前约28ms相位差在F405接收源时刻的比较中仍存在；在该时戳正确的前提下，**源时戳之后的UART4排队不可能解释这部分源相位**，它可以另外叠加主机到达延迟。TI M0内部滤波/测量响应是合理待查项，尚不能断言28ms全来自模块；接收中断延迟、时戳定义与跨时钟映射误差也未独立标定。

按现有8N1配置，gyro UART5 230400的5字节报文线上约0.217ms，AA/BB一对约0.434ms；F405→RDK UART4 921600的95字节TYPE08约1.031ms。仅靠继续提高波特率，不能解释或保证消除约28ms相位。这里计算的是理论字节时间，不是测得总延迟，也没有确认模块支持更高波特率。

## 向RDK并接的边界

RDK同时直接接收同一模块输出，可以帮助绕过并对照F405接收后的转发路径；**不会消除模块本身已经发生的滤波延迟**。是否使用还涉及实际TTL/电平、端口和配置发送权，尚未核对，不授权本轮改线或让两端同时配置模块。先完成现有路径核查，再由用户决定；不把并接当成保证低延迟或零漏检的方案。
