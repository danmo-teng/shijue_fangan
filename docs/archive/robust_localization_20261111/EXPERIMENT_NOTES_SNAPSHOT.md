# 鲁棒定位实验版本

2026-11-11。用户要求优先处理T265慢漂、雷达不可用、T265启动失败/掉线及轮式单源边界；重要改动先放可运行测试版本。基础HEAD为9e906ab，正式默认及比赛业务未切换。本文件随本轮验收更新，不代表地面精度通过。

## 结论及边界

T265缓慢漂移不会自动被confidence发现。两面有效围栏能约束XY时，现有雷达扫描时刻校正仍保留；只有单墙时仅修可观测轴。完全没有围栏时，T265与轮式的差异只能表明冲突，不能单独证明谁对。两路共同漂移或轮式纯平移打滑可能没有足够独立证据，不能承诺仍然准确。

本版保留正常连续T265锚点＋真实轮尾段、主yaw和围栏约束，不引入外部位置加权平均或全局SDK速度积分。新策略显式启用，不能把“代码支持”“API返回true”或软件用例通过写成实际融合精度通过。

| 条件 | 实验处理 | 仍不能保证的量 |
| --- | --- | --- |
| T265慢漂，有足够围栏 | 扫描时刻位置校正；长基线运动冲突和连续双轴墙证据选择来源 | 错墙、遮挡、共同先验带来的误差仍需现场核对 |
| 单墙或无墙，SDK/轮冲突 | 保留当前轮式退路并标记T265可疑；无独立证据不宣称已诊断故障 | 无墙方向及双路共模漂移 |
| T265启动失败、从未输出Pose | 唯一UART继续；真实轮＋主yaw有明确场地参考即可传播 | 轮滑造成的XY误差；没有参考时不能凭空生成场地坐标 |
| T265明确掉线 | 实际SDK不可用事件，轮式继续，不伪造Pose | 掉线期间轮滑；无新轮反馈时不编造运动 |
| 同一设备重新挂接、真实新SDK会话 | 同一owner重开；按真实SDK/主yaw对齐旋转与平移，保留场地参考 | 无地面约束时旧累计位置误差不会凭重连消失 |
| 两路均被连续双轴墙运动反驳 | 明确双疑、继续有标记的轮式尽力传播，暂停新的可疑轮速注入 | 暂停发送不能立刻清除SDK此前的轮速影响 |
| 业务阶段主动排轮 | 不补空转累计；SDK也做单间隔连续性处理 | SDK同时不可用时保持最后支持的估计，不冒称车辆静止真值 |

## 输入与恢复

原动态地图增加`--experimental-robust-localization`，未指定仍用原策略。实验依赖原生运动库，失败会明确报告依赖问题，不能静默退回旧算法后自称鲁棒版。底盘UART和SDK各一个owner，雷达仍用原几何链。

有真实围栏时沿用原四个90°等价解、初始车头接近+X的分支。没有围栏且SDK未启动，允许显式提供已知起点，沿用同一入口：

```text
--experimental-robust-localization
--initial-center-m X Y --initial-yaw-deg DEG
--initial-reference-kind measured|assumed --reference-description "实际摆放依据"
```

`measured`与`assumed`分别记录，不把软件默认当测量。现有stdio入口也支持`set_reference`，需要真实运动/主yaw支持。M冻结选中输出、G录入独立实测；没有SDK时原始SDK字段保持空，不能用轮式坐标填充SDK CSV。

SDK配置、启动或明确设备移除不会再结束实验UART服务。实际T200新增设备事件只触发一次重开，其他相机不触发；本机明确SIGUSR1可触发一次重开，没有定时轮询重试或新增MCU握手。每次真正pipeline.start生成SDK会话ID，不声称它彻底清空了设备估计器。

桌面USB准备与shell固件预加载失败时，实验路径记录真实错误后继续owner；一次准备后不重复上传。03e7:2150固件启动态仍依赖已有boot管理链，**本改动没有根治该硬件上电故障**。当前验证范围是原fresh动态入口；手工导入地图的原超时退出流程未纳入本次鲁棒化。

## 连续性与仲裁

原始SDK Pose始终保留。选中轨迹只对有完整四元数、相邻帧号及连续速度支持的单采样间隔纯位置跳量做速度过桥，然后一次重基准；不关闭pose jumping，不恢复旧EKF拒绝门。roll/pitch同时变化、缺姿态、速度冲突或缺帧不冒充纯位置重定位。大于50mm的长时间真实位移本身不是跳变证明。

当前工程条件为相邻位置/速度位移差超过50mm、完整姿态变化不超过0.10rad、两帧速度差不超过0.20m/s，速度模不超过1.5m/s。这些不是实测误报/漏报保证，后续对照实际日志和地面真值；不能不断改阈值把结果调好看。

SDK与轮式位移比较不再每25cm清基线，避免持续3%之类的小漂移每段都低于门槛而永远看不见。双方静止/低运动量时，明显墙位移冲突也可进入原双轴证据判断，不等累计25cm才处理。轮式已可疑后，SDK位置重定位不能冒充轮式已恢复；SDK也异常则保留双疑，不能偷偷恢复可疑SDK轮输入。

SDK输入按既有B→C公式，外参T/W=0。输出速度改为与位置相同的固定地平面坐标，完整四元数/角速度杆臂只补一次；安装候选、比例1.000不变。重开SDK或显式停/续注入边界丢弃未配齐的旧运动，不将暂停前区间在恢复后集中补发；保留身份/时钟上下文，不增握手或年龄门。

## 第二批：数值失效、首次坐标绑定与主yaw相位实验

SDK原始Pose出现NaN/Inf或零四元数时，先保留原始CSV，再跳过不能计算的投影，并单次发布真实数值失效事件。连接中的SDK与可用SDK运动分开记录，真实轮式退路继续；没有伪造Pose、零速度、设备拔出或自动停车。后续实际有效Pose可以恢复处理。原SDK生命周期检查不增加年龄门。

无SDK时重复绑定已选中坐标，保留尚待首次SDK绑定的旋转/平移状态。围栏自动初始化明确记录自己使用的真实运动坐标来源，不能仅因日志有旧SDK帧就把轮坐标误认成SDK坐标。两种情况均在原运行检查加入“首次SDK来自遥远原点、不同航向”的断言。

业务排轮或SDK单源阶段不再塞入无用途的轮配对队列；完整SDK原始/连续历史仍保存。原比赛第二场修复前出现1951次配对队列覆盖，不等于原始SDK丢1951帧，修复前报告保留。

历史约28ms相位接入为独立、显式工程实验：

```text
--experimental-robust-localization --experimental-primary-yaw-phase-ms 28
```

默认相位仍为0，正式默认不启用。主yaw原始事件时间和独立yaw/rate ID不改；派生历史使用event−phase，当前端点仅从真实yaw锚点用已收到的实际角速度有限预测至该yaw的source event，不外推到迟到的主机接收时刻。重复yaw、单独rate到达和重复查询不能把预测无限向前推；超出这一个真实事件支持后持有端点，并明确标记。SDK轮输入的区间配对与B→C换算不变，不额外等28ms，不读取高频新计时器、不增加握手。

这不是物理延迟标定，恒角速近似不代表加减速完全正确；误差与切源变化须看同输入回放和后续地面核对。派生航向与原始主yaw历史、预测支撑及身份同时可查，雷达去畸变、轮式投影和场地航向使用同一派生视图。

约01:38的统一Release构建通过原核心、主yaw时间线及CTest2/2；5项精准Python检查为无SDK/重接、围栏初始化、默认逐输入兼容、入口参数及相位运行接线，均通过。相位用例含2秒迟到接收，但预测仍止于真实source event，不形成2秒虚构转动；这是软件输入检查，不是实测传感器时延。原始两场逐事件回放与后续SDK不等停轮修复另行记录，不能混用不同构建结论。

## 原始比赛日志对照与28ms候选结论

已完成两场真实输入的离线重算，原始日志保持只读。第一批冻结库以当前C++ legacy策略与robust0逐事件比较；第二批冻结库再比较legacy0、robust0、robust28。各批实际库SHA、输入SHA、到达时刻代理和无法覆盖的尾部都在[完整报告](reports/robust_localization_20261111/NATIVE_REPLAY_ANALYSIS.md)及[相位报告](reports/robust_localization_20261111/phase_source_event/PHASE_ANALYSIS.md)。不能把后续工作目录的新库算成本批已测。

第一场当前墙预修正RMS为legacy 9.179mm、robust0 8.718mm；第二场为12.049mm、10.838mm。它们只是原accepted墙与选中历史的一致性，墙受原prior/去畸变影响，SDK也已融合旧轮输入，不是独立地面精度。单间隔SDK过桥分别1/17次，异常中不满足完整姿态/速度条件的4段未硬改为正常；第一场396mm原始跳量被过桥到0.470mm，但当时两版本来就已选轮式，不能宣称控制轨迹改善了39cm。

**默认相位保留0ms。** 第一场0→28ms墙预修正RMS为8.718→8.842mm，实际SDK系/轮式切换4→6次；第二场仅约0.0013mm RMS差异且来源行为相同。28ms保留实验候选，不能凭历史相位重复出现就推广全链。真实30.295秒业务排轮段的无用途pending覆盖1951→0，位置统计保持不变；这是配对积压修复，不是精度提升。

## 后续增量：运动支持、状态和角残差

正常SDK的真实新Pose不再等轮反馈才能更新选中轨迹。晚到的轮增量仅用于其真实支持区间的比较，不能让已发布轨迹倒退或重复叠加。SDK重接时即使轮已停止更新，真实有效Pose也能续接。围栏裁决切换来源时保留已发布的较新运动尾段，仅施加同一次历史位置平移；不删除尾段，不把旧墙时刻冒充当前时刻。

真实轮区间ID或区间端点出现断链时，继续接收后续合法实测区间，明确标出缺失运动，清除跨缺口比较基线；不把未收到的区间当零位移。该判断比较原生连续区间身份，不读取额外now，也不是年龄门。完整缺口表只在低频快照输出，高频输出只带计数和最近一次真实断链。

增加`held_estimate_increment_unknown`和`sdk_motion_available`，区分“仍持有估计”和“有实际SDK增量支持”。仅根据明确SDK不可用及现有排轮/无轮历史事实表达，不靠静默时间推断失效。保留VALID/ready控制语义；随意清它们会触发原比赛暂停，并非仅改显示。真实SDK流不可用时旧confidence=3不能再设T265Good。

原生编码器与主yaw角残差已形成纯观察模块：原始07轮计数区间与08累计yaw历史在同一MCU轴插值，计算单区间及约100ms连续整区间窗口。采用当前`L=0.130m`、`k=pi*0.070/1061.268m/count`，轮式转角为`k*(d1+d2+d3)/(3*L)`，不把0.115m离线候选冒充已标定值。每条结果保留实际轮ID、yaw支撑ID和原始事件时间；不借用SDK角度，不外推缺失gyro端点。窗口复用已有异步日志，不增加高频计时。

此观察器**不自动判滑、不控制SDK输入、不改变来源选择**。角残差为零仍不能排除纯平移打滑、共模误差或错误轮臂；新逻辑的误报/漏报和绝对运动精度仍未实测。非零相位继续是显式候选，原始数据不改。最终本批统一构建、运行接线及断连/重接验收结果另列，不能用纯模块通过代替实际Runtime已验。

SDK的关键状态只有一个有界“最新待发”槽，IPC满时复用原循环非阻塞续送；普通Pose仍不排队积压。发送前先处理待发状态，避免新有效Pose先到、旧失效事件随后反向覆盖。原始状态的时间不重写。接收端观察到实际Pose IPC EOF/硬接收错误时退休SDK运动支撑，注明物理USB状态未知，继续轮式而不把普通EOF锁成永久进程错误；真正新连接/Pose可以恢复。没有增加MCU握手、计时巡检或等待。

新SDK会话首帧confidence=0时仍保留旧有效Pose诊断，但后续有效帧只与**同一真实SDK会话**的frame基线比较。不能拿旧会话frame1000挡住新会话frame2，也不能靠清空原始日志掩盖这个边界。

## 本轮重新核对的官方边界

Intel的[T265 Specification Update（2021，PDF第8页）](https://dev.realsenseai.com/download/16547/)将运动/静止漂移、重定位漂移和Pose NaN列为已知问题；因此confidence正常或持续发包不能保证位置准确。文档建议外部标记纠偏，并说明NaN时停/启流可能恢复；没有给出永不漂移的保证。我们复用场地围栏提供外部位置约束，不在本轮引入AprilTag系统。

同一官方勘误列出经Hub上电时固件未加载的已知问题，建议Hub/控制器先枚举再给T265上电。本机01点后的只读USB清单仍是03e7:2150；本轮没有进行复位实验，不能把实验轮式退路当成USB故障已解决。

[SDK v2.50.0 T265说明](https://github.com/realsenseai/librealsense/blob/v2.50.0/doc/t265.md)规定SDK定位中心在双目之间、世界Y随重力向上，并说明轮速有助于轮式机器人跟踪；外参仍按该真实坐标定义，未叠加内部IMU偏移。官方pose jumping的位置跳量与连续运动需分开，原始数据继续保留。
