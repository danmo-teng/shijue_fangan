# F405 NormalDebug 后续配套接口任务（本轮不执行）

## 2026-10-31：T265官方轮速输入的必要配套任务

用户已确认当前没有更新接口，选择上位机严格门控；当前旧帧保持参考用途、不注入。
请下位机另行设计兼容合同，本窗口不修改/烧录下位机，也不分配草案TYPE/opcode。

1. 发布真实轮反馈区间的起止采样tick、三路原始累计计数或区间实测车体系forward/left速度，
   单位明确且X前/Y左；保留新F405运动学与原始计数核对。速度是区间平均或滤波值需明确，
   提供滤波延迟及有效区间，不接受目标速度。反馈异常/不可靠/打滑可疑应可标为不可注入，
   不以计数器仍在发包或status低三位代替完整测量健康。
2. 主gyro角速度保持CCW正，独立发布真实角速度采样tick、健康/饱和/恢复状态及唯一源样本ID。
   不把yaw与rate当同一采样，不以重复打包100Hz作为实际新rate100Hz；给出两者的真实更新频率、
   旧值重发规则、内部滤波/链路延迟及抖动。现0x1F最大age不能替代这些字段。
3. 轮反馈与gyro采用同一MCU时间基准，或给出可验证的映射；明确tick单位、回绕规则与重启身份boot epoch。
   reset_reference不重置原始计数/gyro，若局部reference epoch变化则明确范围。boot epoch不能用主机UUID替代。
4. 支持主机对时或可证明的采集→发送延迟界，便于上位机把capture tick映射到CLOCK_MONOTONIC，
   记录offset/drift/uncertainty。当前上位机初始预算：时间不确定度≤5ms、gyro间隔≤20ms、
   最老轮区间端点到SDK调用含不确定度≤50ms；需实测带宽/排队/批量发送，不能仅以平均频率承诺。
5. 给出实烧固件身份/NormalDebug服务证据、机器可读合同与正反向/横移/自转/组合运动hex示例。
   示例说明各自采样tick与到达顺序、缺包/重启/回绕/异常gyro，禁止靠0x15/0x1F相等SEQ推断同步。

上位机本机标准事件字段见[t265_f407_center_debug.md](t265_f407_center_debug.md)；
这是解码后适配合同，不是已经实现的UART接口。新版下位机合同完成后，须单独审核并更新唯一底盘客户端，
验证采样时间和epoch后才可产生capture_time_qualified=true事件。现有解析器不会伪造这些事件。

## 已有后续任务

依据下位机文档提交a54ee465、固件实现14157e6。当前上位机只适配已有0x19/0x1A、
0x15、0x1F；以下能力明确未实现，不是本轮实车或固件改动授权。

1. UART4能力/身份查询：定义无运动、停止或归零副作用的请求/响应；给出版本、板型、
   NormalDebug运动服务与比赛服务区分、固件标识、功能位、关联nonce和重启身份。
   不以文本SERIAL_V3、文档修订号或MODE=5冒充线上协商结果。
2. 实测车体系速度：版本化发布反馈forward/left及必要质量标志，保留原始轮计数；
   明确单位、符号、共同采样快照、tick、采样区间、滤波延迟和截限规则。
   目标速度不作为测量；已有0x1F gyro继续原生CCW正，并说明其与速度采样的时间关系。
3. 组合动作：现Motor_MoveSpinAngle仅内部C函数，结束条件为转角并无平移距离终点。
   另行定义speed/direction/turn/rate的完整线上事务、原子接受、身份、完成/取消/拒绝及超时，
   冻结明确合同后再由上位机实现move_spin_angle，不用两个顺序动作伪装同步组合。
4. 严格动作身份：若需排除跨重启及SEQ回绕的迟到请求/回执，需要线上boot/reference epoch、
   足够动作ID或nonce和去重规则。当前主机UUID不能替代板端身份。

实际验证范围。未定编号前上位机保持不支持，不发送探测性未知包。
