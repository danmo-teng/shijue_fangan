# 可直接复制给F407：聚集130°对正360°刷新与恢复锁存

本次核对下位机2d1957a。仅要求修改下述逻辑，不要求修改LCD、调试输出或增加测试。
不生成/应用F407补丁，由下位机负责人实施。

## 1. 问题与上位机已改部分

最新日志：23.75秒锁定绿色聚集目标，track60随即消失，多个候选重关联分差过小，
上位机无限重复旧APP(395,716)，F407在130°对正时始终认为横向误差245 px，持续原地转圈。

上位机已修：
- 原track消失后，按同一聚集区域的空间连续性确定性选择新锚点，不因同堆两个绿色相似而永久拒绝。
- 每个真实新frame_sequence才能刷新聚集APP的有效期；重复旧帧不能延长。
- 旧坐标只保留普通APP已有动态缺帧窗口，之后发HOLD。新帧重新确认后才恢复APP。
- mode20+130°聚集对正期间，用新鲜T265相邻航向差累计实际转角，达到360°即持续HOLD，
  进入WAIT_SEARCH_RECOVERY，等待mode24→mode3。普通SEARCH不受这个360°限制。
- 恢复清旧track、聚集框、APP、审核；首件标志、投送次数、开局策略和藏堆完成标志保留。
- 当前搜索一圈内暂缓失败track及同类别重叠区域，优先其他候选；重新搜索一圈或选中新批次后解除，
  不永久拉黑物资。第一次正式投送仍只找绿色，夹内审核只允许单绿色。

## 2. F407聚集对正累计360°

仅在APPROACH_CLUSTER_ALIGN进入时初始化：last_yaw、累计转角、恢复锁存标志。
基于IMU每次有效的新航向样本，计算归一化到[-180°,180°)的相邻差值，累计绝对值。
例如359°→1°记2°，不能记358°；一圈后的起止角相同不能被当作0°。
在同一对正阶段内，重复APP、坐标变化、新SEQ不能清零累计值。
离开该阶段、开始新的聚集任务时才清理本阶段计数。

如果已达到正常横向对正条件，按原流程去140°和mode38。
如果仍未对正且累计实际转角>=360°：
停止对正→锁存本轮聚集恢复→清旧目标/转向跟踪→进入mode24。
不要直接跳去mode3，更不要直接GRAB。

## 3. 聚集恢复不能被旧APP/旧视觉报告取消

2d1957a的两处现有逻辑会与强制刷新冲突：
1. task_process_approach_recover在found且经过500 ms时直接回TASK_APPROACH。
2. task_accept_mission允许APPROACH_TARGET在TASK_APPROACH_RECOVER立即进入TASK_APPROACH。

请给“聚集强制刷新”增加内部恢复锁存，不改变UART命令：
- 本地聚集360°触发时置位；聚集对正阶段持续HOLD进入恢复时也置位，
  这样兼容上位机360°兜底和旧坐标失效后的HOLD。
- 锁存期间，mode24收到旧CLUSTER/APP或旧全局目标报告，不能回APPROACH。
  不得靠持续新SEQ判断它是新物资；原坐标本来就在不断换SEQ重发。
- mode24持续HOLD按原恢复时序完成，并在至少看到一次恢复期间HOLD后进入mode3。
  在看到HOLD前可重复上报mode24，避免上位机漏采样仍以为旧任务在执行。
- 进入mode3解除恢复锁存，允许上位机从新视觉帧发送新的APP。
- 普通非聚集APP目标在500 ms内恢复可取消恢复的原逻辑保持，不扩大成所有任务一律强制刷新。

## 4. 首件任务状态不可被恢复清除

刷新只是放弃一个未对正的目标，不是完成投送，也不是重开整场比赛。
不得修改first_delivery_done，不得把已藏堆改为未藏堆，不增加投送数。
first_delivery_done=false时，恢复后仍要求首件正式投送恰好1件GREEN。
后来物资仍按GREEN/CORE合计最多2件、伤员单件；超量仍走分离。
可以再次靠近绿色聚集区域审核后分离出单绿，不能因为画面出现四绿就直接抓四件运输。

保持mode38审核、20°观察、正常mode24、扫障42～46、进攻/防守藏点及无障碍ENTER流程。
不要新增超时FAULT/ABORT，不放大横向对正阈值来掩盖旧坐标，不把普通SEARCH的旋转算入聚集360°。
