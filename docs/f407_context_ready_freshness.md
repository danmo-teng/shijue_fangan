# 可直接转交F407：审核READY、通信/视觉帧龄、任务/动作归属

核对基线：3319ab5。上位机已同步修改Python任务程序和C++串口转发/状态解析。
必须配套更新F407后运行；旧固件没有上下文回执，上位机不会静默退回仅靠8位ACK的流程。
本说明只要求逻辑和协议适配，不要求LCD、调试输出或新增测试。不要修改1秒投送策略。

## 一、优先修非法审核就绪握手

TYPE=0x17状态flags增加bit6=0x40：AUDIT_READY。
- READY=0：当前审核尚未收齐3个不同真实视觉结果。
- READY=1、VALID(bit4)=0：审核已收齐，组合非法，可处理释放/分离。
- READY=1、VALID=1：审核已收齐且合法。
普通审核映射audit_received；mode43映射独立扫障审核是否收齐，不能把正常旧审核READY带入。
进入新审核、视角离开/回到140°、任务改变时按现有规则清缓存及READY/VALID。

CARGO_AUDIT单帧接受可以ACK，但不得因此置READY。
上位机非法审核在READY=0时持续使用真实新frame生成新audit_id；收到READY才发送RELEASE/DISPERSE。
重复同一视觉帧的audit_id不变。下位机同时检查下面的vision_frame，
同一画面即使变换SEQ或audit_id也不得重复累计；不能只相信STABLE位。
VALID成立必须同时READY成立。mode37、22、40等既有完成语义保持，不用ACK替代机械完成。

## 二、保留15字节帧，增加成对上下文

0x19/0x1A以及0x1B/0x1C已被下位机不同编译配置的运动调试协议占用，不能复用。
新增TYPE=0x1D COMMAND_CONTEXT、TYPE=0x1E STATUS_CONTEXT。
帧头尾、CRC16及每帧长度仍与旧协议相同；多字节payload字段为大端，CRC仍原格式。

上位机每次发送连续两帧：
  0x1D上下文 → 0x18原命令
两帧使用相同SEQ。0x1D的P0～P7：
  P0/P1 task_id uint16
  P2/P3 action_id uint16
  P4～P7 vision_frame uint32
0x18的动作opcode、坐标、flags、audit_id等字段完全不挪用。

vision.c仅在收到CRC正确的1D后，再收到紧邻且同SEQ的18时，原子提交该命令及上下文。
前半帧丢失、SEQ不匹配、CRC失败或中间插入其他帧，不能沿用上一次上下文执行裸18。
重发下一完整帧对即可恢复，不增加FAULT/ABORT。
既有赛前0x11配置保持单帧；显式裸ABORT仍允许用于退出/取消。
正式比赛的APP、NAV、审核、抓取、释放等必须使用完整帧对，不能用裸18绕过归属检查。

F407每次反馈连续两帧：
  0x1E状态上下文 → 0x17原状态
两帧使用相同的下行SEQ。1E的P0～P7：
  P0/P1 当前已接受任务task_id uint16
  P2/P3 当前已接受动作action_id uint16
  P4    已接受opcode uint8
  P5    action_status：bit0=该动作已接受，bit1=该动作已完成，其余0
  P6/P7 0
1E/17必须来自同一次状态快照。上位机仅给紧邻、同SEQ配对的状态附上上下文，缺失则标无效。
上位机推进仍要求对应mode/GRIPPER_CLOSED/AUDIT_READY/AUDIT_VALID等条件；bit0不是完成。
当前上位机主要消费bit0及对应完成mode；bit1应如实反映机械或审核动作的完成，不得因ACK就置位。

## 三、三种编号不能混用

SEQ：UART传输编号，约100 Hz重发时更新，只代表通信。
vision_frame：上位机每次完成一个新摄像头帧推理后才增加，摄像头重启也不在本会话内倒退。
task_id：一轮目标任务，重新选择批次时更新，track重关联/类别复审不因此重开任务。
action_id：该任务内动作编号，APP→AUDIT→GRAB→NAV等转换才更新。
同一APP坐标更新、同一NAV剩余距离更新、审核续audit_id、重复动作命令不更新action_id。
HOLD/PAUSE保留当前task/action，作为该动作的控制覆盖，不得重置动作或视觉年龄。

上位机会在新的赛前配置会话中选择随机初始编号，其后按uint16递增；
仅通过既有赛前配置/重新启动握手建立会话，不能允许陌生编号随意接管进行中的任务。
会话内采用16位序号顺序规则拒绝旧task/action，绕回按模65536处理；
任务更换必须同时清除上一任务的目标、视觉代号、动作完成证据和审核缓存。
状态自动进入mode23/24/3/40等时保留其所属的已接受上下文，直到接受上位机下一动作。
重复相同编号且相同opcode只更新连续控制参数或ACK，不重新初始化机械动作原点、预算和计时。
相同动作编号改变普通opcode应拒绝；HOLD/PAUSE覆盖以及恢复原opcode是明确例外。
拒绝过时命令不能把它的编号写成“当前已接受上下文”。
mode41、聚集强制恢复、找回失败等取消动作后，要标记旧动作已取消；
不能因旧APP帧对再次到达而重新激活。HOLD仍可ACK，重新选择目标使用新的task_id。

## 四、分别处理通信年龄与视觉年龄

维护两个独立时间：
1. last_command_rx_ms：有效、归属正确的完整命令帧对更新。
2. last_visual_update_ms：APP/CARGO_AUDIT携带新的非零vision_frame才更新。

重复帧对的新SEQ仅更新通信时间；相同vision_frame不能刷新视觉时间。
vision_frame=0表示无新的视觉观测（机械动作或占位包），不得当作新画面。
同一任务内倒退的视觉编号不能覆盖较新的目标；审核必须消费对应当前审核阶段的新帧。
不要再以remote_target_generation随SEQ增加来判定真实视觉新帧。

建议通信失效阈值500 ms、APP视觉失效阈值500 ms，保持参数集中配置。
这两者不是机械动作超时，不能重置动作进度，也不引入整场FAULT/ABORT。
上位机转发器在命令文件250 ms未更新时会停发；F407仍必须根据last_command_rx_ms自行停止使用旧指令。

分类处理：
- APP：画面过期停止按旧坐标转向/前进，进入可恢复观察/HOLD；新真实视觉帧可恢复。
- 普通NAV、RETURN：命令过期不继续使用旧H/D，停车保留阶段；新有效同动作H/D恢复。
- 等待审核：过期帧不累计，等待真实新帧；已收齐的结果只能属于原任务/动作。
- 已接受的合爪、张爪、有限编码器动作及扫障本地后退：与命令接收判定分开，
  按该动作既有完成/恢复规则执行；不能因短暂帧龄变化反复取消并从头执行。
- 完成后的阶段不能用已过期的缓存APP/NAV自动启动下一动作。
- mode41仍由本地恢复控制，HOLD只ACK。mode24聚集恢复的HOLD握手保留；
  通信中断时可以在可恢复等待中停留，恢复通信后继续握手，不用旧APP取消恢复锁存。

## 五、ACK与动作完成

ACK只表示该上下文命令接受；不能把SEQ变化解释为夹爪、转向、行程已经完成。
上位机已改为核对task/action、接受opcode和action_status，再配合原完成mode推进。
例如mode32/33/34是释放完成，mode11是对应ALIGN完成，mode23是对应合爪后审核，
mode40是扫障取回复审完成。旧任务相同mode的状态不能完成新任务。
没有1E回执时，上位机会重发当前请求，不据旧状态推进，不静默回落到旧ACK判断。
因此必须更新F407并使用本次重新编译的上位机localization串口程序。

## 六、1秒投送策略不变

mode15视觉观察最多1秒，未确认仍发送TASK_COMPLETE，完成依据记录delivery_visual_timeout。
F407按原协议结束本趟并退出；不得擅自改回长时间视觉等待。
它仍表示本趟流程结束，不等于视觉证实投送成功；不修改目前计次与首件推进策略。

保留开局任意非空藏堆、首件单绿、后续普通/核心最多2件、伤员单件，
进攻/防守、360°聚集刷新、无标定走廊与扫障42～46全部既有业务语义。
