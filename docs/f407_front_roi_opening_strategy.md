# 可直接转交F407：前方ROI与开局进攻/防守对接

已核对下位机77b9026。本次修改主要在上位机，不要求修改LCD、调试输出或新增回归测试。
现有扫障42～46、初始藏堆和NAV协议继续使用，不新增UART字段。

## 上位机已修改

1. 障碍候选、扫障目标选择及track重关联共用前方像素区域判断。
   目标框中心和底部中心必须在区域内；已在安全区、或中心/底部落点在安全区内及入口边界，
   不作为走廊外部障碍。此规则只用于扫障，不放宽正式投送成功判据和夹内数量审核。
2. 二次视觉ALIGN后用新安全区框构造走廊；mode42如有当前120°安全区框继续使用该走廊。
   无当前安全区框或切到140°时使用当前相机的中央前方通道，不沿用旧视角安全区框。
   mode44找回原物资使用独立中央搜索通道，不使用朝围栏的旧走廊。
   重建track必须位于前方区域且与上一目标位置连续，不能全屏挑选同类别物资。
3. 屏幕绘制与目标筛选使用同一多边形，对齐/扫障阶段隐藏容易混淆的夹爪ROI。
   显示底图与检测结果使用同一摄像头帧；夹内审核阶段仍使用原夹爪ROI计数。
4. 启动界面新增进攻/防守互斥选项，默认进攻；保存session.json的opening_strategy。
   旧session没有此字段时也默认进攻。命令行支持--opening-strategy attack/defense。

## 开局藏点坐标

所有坐标仍是同一场地坐标系，单位米，定位目标是小车旋转中心。

进攻：对方安全区物资半区围栏场地侧表面前400 mm。
围栏表面|Y|=1.14，因此目标|Y|=0.74。
- 本方红：X=+0.15，Y=-0.74。
- 本方蓝：X=-0.15，Y=+0.74。

防守：原藏点仅向远离最近左右边界的方向内移150 mm，前后Y不变。
- 出发区1/3：X=-0.70；出发区2/4：X=+0.70。
- 本方红：Y=+0.55；本方蓝：Y=-0.55。
距最近左右边界从650 mm增加到800 mm。

## 下位机应保持的逻辑

1. 进攻/防守仅改变上位机藏点坐标，不改变红蓝方配置、不改变出发区、不重置定位坐标。
   不因藏点位于对方一侧而把本方配置切换成对方。
2. 开局仍INITIAL_STASH=1，任意非空稳定审核→GRAB→mode23复审→mode22。
3. 收到NAV时继续根据audit_initial_stash置route_to_stash，执行上位机实时H/D。
   不在F407另写死进攻或防守坐标；沿用T265计算H/D的原导航链路。
4. 到达藏点后接受RELEASE_BOTH，完成mode34；保持现有退让、RETURN_CENTER和mode3握手。
   进攻藏物资仍是临时放置，不能转成STAGE/ALIGN/ENTER，不能置first_delivery_done。
5. 后续正式首件仍单绿色；之后普通/核心也仅单件、伤员单件，正式安全区仍为本方。
6. mode42只执行上位机给出的扫障目标像素。没有APP时保持已有局部搜索/恢复，
   不使用全局视觉报告自行替换成屏幕其他位置的同类目标。
   mode44的200 mm累计找回限制和mode46失败返中保持不变。
7. 无障碍直接ENTER保持不变；homography和relative_xy_m=null不作为推进限制。

77b9026已有route_to_stash实时H/D处理，本功能不需要新的下位机协议修改。
若实车固件额外硬编码藏点或自主替换视觉目标，去掉这些与上述契约冲突的分支即可。
不更改原导航坐标变换、普通投送点、扫障200 mm动作或边界恢复阈值。

最新运行还存在多次独立mode41恢复，不能把所有往返都解释为ROI误扫。
本次不会通过屏蔽mode41掩盖F407内部定位与边界判定问题。
