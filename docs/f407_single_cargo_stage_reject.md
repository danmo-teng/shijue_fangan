# 可直接转交F407：单件正式运输、分离总次数和mode48拒绝恢复

核对基线9d4f07f。本次上位机已修改实际代码，F407请配套以下逻辑。
不要求LCD、调试输出或新增测试。不新增命令、帧类型；仅使用现有0x1E的保留位。

## 1. 进攻藏点离对方围栏45 cm

上位机进攻藏点最新由围栏前400 mm再增加50 mm至450 mm，小车旋转中心目标坐标：
- 本方红：(+0.15,-0.69) m。
- 本方蓝：(-0.15,+0.69) m。
防守坐标不变。INITIAL_STASH、T265实时H/D、释放和返中仍为原流程。
F407不写死藏点，不修改红蓝方、出发区、定位原点或本方正式预备点。

## 2. 正式运输严格单件，优先普通

- INITIAL_STASH优先按非空处理，开局多件藏堆不受单件限制。
- 首次正式运输仍只能恰好1件GREEN。
- 首件完成后，只允许恰好1件GREEN或1件CORE；伤员仍单独1件。
- 2件普通、2件核心、普通+核心、伤员混装、危险/未知均不得正式NAV。
- task_audit_semantic及所有正式审核将上限2改为1；MIXED_MATERIAL不是一种合法单件类别，
  即使错误数据声称total=1也不能放行。保留现有左右总数一致性条件。
- 计入完整夹爪ROI的实际数量，不把2/3/4件截断为1。协议计数字段不变。
- mode21/38、mode23、mode45找回原物资、mode48运输复审均一致。
- mode43取障仍使用独立非空语义，可以抓危险障碍；不能套用正式单件限制。
- 普通优先由上位机在搜索/聚集选择与选侧时执行。已抓住的合法单核心照常送，
  不因途中又看到绿色就中断运输。

## 3. 分离总次数和当前侧松角次数分开

现有task_prepare_separation换侧将separation_attempts清零，与上位机总次数不一致。
请区分：
- separation_total_attempts：同一目标任务已接受的物理带侧分离总数。
- separation_side_attempts：当前保留侧的连续递进次数，控制松角。

带侧DISPERSE或单侧RELEASE真正被接受时，总数+1；重复同action不增加。
无侧20°观察不计入总数。换侧只清当前侧计数、重建该侧夹持基准，不清总数。
当前侧依次相对其第一次松0°、10°、20°，不是叠加为30°。
task_begin_capture_escape、task_capture_observe和第四次请求拒绝均依据总次数。
第三次复审READY且仍非法才走24→47；READY=0不能提前当第三次失败。
禁止通过换侧申请第四次。

合法审核、合爪、NAV、mode48以及同任务的新action不能清总次数。
仅新目标任务或明确结束/放弃该任务才清理；新action和task编号回绕不能伪装新目标。
上位机已保留合法清单锁存前后的总计数，并单独记录当前侧次数。
实际退出仍以F407的mode24/47/3为准，上位机不会凭自己的计数提前RETURN。

## 4. 明确反馈拒绝动作，不把回执延迟当拒绝

仅看到旧accepted上下文，无法判断新请求是还没收到还是已被拒绝。
扩展现有0x1E STATUS_CONTEXT：
- P0/P1：已接受task_id，保持不变。
- P2/P3：已接受action_id，保持不变。
- P4：已接受opcode，保持不变。
- P5 bit0/bit1：接受/完成，保持不变。
- 新增P5 bit2=0x04：有明确的同任务请求拒绝回执。
- P6/P7：被拒绝的action_id，uint16大端。

仅在完整0x1D→0x18帧对已解析、同task请求确实被业务/上下文条件拒绝后置bit2。
不能因为暂时没有收到新命令就置拒绝。
拒绝时不得修改accepted task/action或伪造ACK接受；P6/P7标识拒绝对象。
成功接受该请求或后续新动作后清拒绝标志；新的明确拒绝更新该标志和ID。
HOLD/PAUSE不能把尚未消费的拒绝回执误清掉。
只用此字段报告当前已接受task的拒绝；跨task拒绝不冒充同task反馈。
0x1E→0x17仍同SEQ紧邻发送、同一次状态快照，长度与CRC不变。

上位机只有在task匹配且rejected_action_id等于当前请求action时才修正请求；
否则视为尚未收到回执，保留正常重发，不按等待时间猜测动作失败。
旧固件P6/P7=0、bit2=0不会触发此处理，因此需配套升级F407和C++状态解析程序。

## 5. mode10/48修正路径

mode10拒绝预备点审核且DISTANCE_DONE=0：
上位机采用真实accepted归属，取消旧审核pending，恢复同task实时STAGE NAV。
抵达条件成立后才重新请求140°mode48审核；不改导航目标，不开新task。

mode10已到达但拒绝格式/条件错误的审核请求：
重新构造全零、非STABLE、vision_frame=0的正确进入请求。
不能因等待超时跳过mode48去ENTER。

mode48拒绝ALIGN、改道NAV、释放或错误审核请求：
取消该pending请求，回到TRANSPORT_AUDIT，重新建立frame floor并读取完整ROI。
READY=0继续真实新帧；READY且非法走现有分离/释放；READY且合法才重新选择
定位ALIGN或对应目的地NAV。不能永久重发条件已不成立的旧动作。
新请求分配新的action_id，同task保留，之后重发与H/D更新保持同action。

下位机仍须如实执行已支持的mode48出口：
- 已完成STAGE才接受进入mode48。
- READY/VALID及闭爪满足后接受合法ALIGN/NAV。
- READY且非法时接受对应释放；稳定空爪允许双开放弃。
- 不用放宽接受条件、伪造READY/VALID或超时ENTER来绕过流程。

无障碍ENTER、650 mm/330 mm/s/1500 ms推进保护均保持。
