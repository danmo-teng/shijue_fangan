# 可直接转交F407：无测距视觉扫障协议（本次新增，须配套固件）

请基于F407 16c4b77适配以下接口。上位机已实现；本文件是协议要求，不是F407补丁。
不需要homography，不需要预先知道障碍距夹爪多少毫米。没有障碍时完全保持原投送流程。
本协议优先于历史文档中“CLEAR必须80～600 mm”和“缺homography禁止ENTER”的描述。

## 1. 无障碍

STAGE→定位ALIGN→视觉ALIGN→上位机读取转向后的新画面→像素走廊无障碍
→原ENTER→F407编码器推进→mode15→视觉确认最多1秒→TASK_COMPLETE→退出返中。
没有障碍时上位机不发0x13、不暂放、不进入额外SEARCH/GRAB。
安全区新框缺失仍等待新框；距离为null不影响流程。

## 2. 0x13入口

TYPE=0x18，P0=0x13 CLEAR_SAFE_ZONE：
- P1=CMD_VALID|RED_SIDE（蓝方不置RED_SIDE）。
- P2/P3=0：表示视觉引导取障，不是前进0 mm后立即合爪。
- P4/P5仍为有符号±150 mm，表示暂放原物资的横移方向。
- P6/P7=0。

修改两处校验：Main/Src/vision.c的0x13解析、Task.c的task_safe_sweep_command_valid。
允许P2/P3=0。可兼容保留旧80～600 mm分支，但0必须进入新视觉流程。
接受条件仍为视觉ALIGN完成、原物资已合爪。重复CLEAR只ACK，不重置动作、原点或记录。

## 3. 模式与取障动作

保留mode39：原物资暂放、移障、退回、取回原物资等自主机械动作。
新增mode42 SAFE_SWEEP_APPROACH：原物资已暂放、车已返回走廊中心，可搜索/靠近障碍。
新增mode43 SAFE_SWEEP_AUDIT：相机到140°、CLAW_VISIBLE=1，可开始扫障夹内审核。
不能用普通mode3/20/21代替42/43，否则会混淆原投送批次和当前取障阶段。

mode42期间：
- 复用普通APPROACH的像素对正、靠近和低头观察控制，不要求毫米距离。
- 上位机发0x09 APPROACH_TARGET，P1=VALID|RED_SIDE，P2/P3=x像素，
  P4/P5=y像素，P6/P7=0，坐标为1280×1024画面的目标框中心。
- 新APP更新目标，不得退出扫障上下文，也不得重置原投送任务。
- 暂时无目标时上位机发HOLD；由扫障内部搜索/丢失恢复继续寻找。
  不得因此进入普通SEARCH、丢弃原物资记录或清空扫障行程；新APP到达应能继续靠近。
- 需要夹内确认时进入mode43。mode43没有形成非空审核时，可复用已有靠近/观察恢复，
  如返回搜寻仍上报mode42；不得把空审核当作“原物资丢失”并回普通mode3。

mode43期间使用原0x12 CARGO_AUDIT报文，新增P5审核标志bit6=0x40：
AUDIT_SWEEP_PICKUP（注意是P5，不是P1）。
- vision.c原P5&0xC0拒绝条件应改为只拒绝bit7，允许bit6通过解析。
- 仅在扫障mode43接受带此标志的审核，其他正常抓取/开局/投送状态拒绝该特殊语义。
- 上位机只审核已锁定或重关联的障碍是否进入夹爪ROI，原物资不参与；
  左右类别/计数仍按原协议编码，INITIAL_STASH=0、DESTINATION_INJURY=0。
- 同一次140°观察内，3个不同audit_id的非空审核即置AUDIT_VALID。
  蓝色危险物、伤员、未知、跨左右中线均允许作为扫障目标，不套用正式物资合法性。
  STABLE只作描述，重复ID不累计；空审核打断非空连续计数。
- 上位机每个真实新视觉帧续audit_id，140°未就绪时发同ID非STABLE空审核。
  进入mode43、离开/回到140°或退回mode42时清理本次审核计数和AUDIT_VALID。
- 上位机自身满足3帧且收到AUDIT_VALID后，持续发0x02 GRAB_CONFIRMED（VALID|RED_SIDE）。
  mode43必须按扫障规则接受GRAB，危险物不能触发普通危险拒抓/释放路径。
  重复GRAB只ACK，不重复合爪、不重复推进；执行取障后回mode39。

## 4. 记录实际运动并取回原物资

收到CLEAR时，保存原物资审核、投送目的地、夹爪状态、暂放侧、走廊原点和锁存航向。
扫障目标使用单独审核缓存，不能覆盖原任务、first_delivery_done或开局藏堆标志。
搜索/靠近时用编码器记录实际移动；有转向时同时记录航向/动作段，
不能把累计path_mm直接当作直线前进距离。按记录恢复到走廊中心并执行原物资取回动作。
扫障前进、退出路径不再从上位机接收预测毫米数。

移走障碍并取回原物资后：
mode39→mode23（GRIPPER_CLOSED、CLAW_VISIBLE）→原物资正常3帧审核→mode40。
进入mode23前清除扫障特殊审核标志/计数，恢复原任务语义；上位机此时发送的审核不带bit6。
上位机保留“本次CLEAR已接受＋新鲜mode23夹爪状态”交接，不要求一定采样到mode39。
mode40后仍按定位ALIGN→视觉ALIGN→新画面走廊检查执行，无障碍才ENTER。
途中0x13、APP、AUDIT、GRAB均应在相应阶段可重发；不要因旧命令最后一帧重启动作。

mode41继续按原边界恢复清上下文；上位机同步清除临时扫障目标。
原单次投送最多两次扫障限制、正式危险释放、20°观察、mode24普通恢复、
开局任意非空藏堆、正常STAGE/ALIGN/ENTER及1秒投送确认均保持。

## 5. 部署说明

旧16c4b77会拒绝P2/P3=0的CLEAR以及P5 bit6审核，因此有障碍场景必须先配套更新F407。
无障碍的ENTER报文未改，不依赖新增42/43。
最小联调覆盖：无障碍直送；蓝色障碍取走再取回原物资；目标track重建；
审核掉帧后续ID；重复命令不重启；取回原物资后mode23/40；mode41清扫障上下文。
