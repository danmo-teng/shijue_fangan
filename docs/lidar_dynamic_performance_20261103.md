# 动态定位性能优化：实际结果与精度边界

基线 `27a78c6`，2026-11-03。用户要求核对比赛绑核、优化性能、说明补丁来源和准确性，随后明确选择：
**先隔离雷达工作进程，保持算法**。本轮只改测试路径，未发底盘运动、未清理日志、未修改下位机/正式比赛。

## CPU与算法来源

比赛桌面入口、`run_competition_map.sh`、地图/比赛进程及定位代码均未发现显式CPU亲和性设置；
仓库只对OpenCV设置单线程。这不是CPU绑核。检查时没有运行比赛任务，不能声称测量了比赛进程的实时亲和性。
本次最终调试进程和雷达工作进程允许CPU0～7调度，未保留临时绑核或Python线程切换间隔设置。

提线是用户补丁的 `lidar/static.py` RANSAC＋TLS；墙关联/可观轴解算参考 `fusion/fence_adapter.py`，
运动补偿参考 `fusion/deskew.py`。SDK、底盘客户端及进程接入由RDK测试代码适配，没有整包应用补丁。
补丁 `VALIDATION.json` 明确 `hardware_tested=false`、`rdk_tested=false`；288项检查属于软件/模拟验证。
所以不能因为来自补丁，或通过模拟，就评价“实车准确性优秀”。

## 最终改动

1. `static.py`每轮仍160组、最多8轮，批量生成均匀的不重复有序点对，替代160次小型`choice`调用。
   各点对概率仍为 `1/(N*(N-1))`，同一对内部不重复，不同候选可以重复。随机种子序列改变，
   不声称与原输出逐点相同；残差、支持跨度、围栏、单墙约束及TLS未放宽。
2. `dynamic.py`数组转换只取当前扫描/显示需要的前后采样点，保留完整原历史；
   区间外仍用原两端点外推，不以年龄筛掉数据。新检查覆盖区间前、内部、末端及区间后，结果与完整历史一致。
3. F405内部只读订阅共用一次接收快照，减少重复深拷贝；普通外部订阅仍独立拷贝，隔离检查通过。
4. 新 `lidar_yaw_debug/worker.py` 使用spawn，独占雷达UART并完成解析、去畸变、拟合和原始记录；
   不导入/启动T265 SDK，不打开底盘UART。原地图继续唯一拥有F405客户端，原C++进程唯一拥有SDK。
   Pose/主yaw经1024容量队列转交，时间字段不改写；扫描等待最多4帧。溢出计数，原始记录不按显示频率删减。
   只有GUI最新快照允许合并；起点请求有独立回执，收到后才显示参考已建立。正常退出发送雷达A1、排空日志。
5. 增加 `lidar_worker_events.jsonl`、`lidar_worker_summary.json`，原会话保留规则识别这些明确归属文件。
   metadata记录进程方式、worker PID、抽样实现版本；不提升任何时间/误差模型资格标志。

## 检查结果

同75帧实际桌面雷达数据，提线耗时中位 **122.57→25.38ms**，P95 **132.59→31.46ms**。
39帧线输出完全相同，3帧提线数量变化。相同姿态/原始扫描进入完整墙关联后，两版均0次有效围栏修正、
可观轴结果无分歧。这说明没有在这批桌面数据里新增虚假围栏接受，**不证明真实围栏精度相同或更好**。

现有 `test_f407_motion_protocol.py` 通过：原协议/轮速回归、已知0.7m/s＋360°/s去畸变、单墙仅一轴、
历史窗口等价、只读订阅隔离、GUI，以及新进程在虚拟串口上的收包/参考/退出/日志检查。
虚拟串口测试不打开物理底盘或SDK，不作为实车结果。本次没有改C++，未重复不相关的整套构建。

## 准确性与下一步

现在证明的是：在这次桌面静止负载下，约5000点/秒级雷达输入、200Hz Pose与约50Hz官方轮速输入可并行处理。
没有测过新动态入口的地面位置/角度误差，没有有效3m围栏墙修正（桌面并非该场地），不能称精度优秀或全速已验收。

批量RANSAC是最小实现优化；方向受主yaw约束的一维投影/聚类可能进一步降耗，但会改变杂物识别和墙关联，
也更依赖主yaw方向误差。霍夫方案同样需要明确角度/距离分辨率和支持判定。没有证据证明当前方案更准，
也没有证据允许直接宣称替代方案精度等价。按用户选择，本轮保持RANSAC/TLS/几何判定，先完成执行隔离。

下一项是用户在正式1号(-1.35,+1.35)m、135°确认静止墙约束，再通过现有按钮进行必要短距/高速测试、停稳记点和实测录入。
不得自动启动电机或顺序执行完整矩阵。安装外参、比例1.000、pose jumping、官方输入定义及正式比赛均保持。

机制参考：[Python线程与GIL](https://docs.python.org/3/library/threading.html#gil-and-performance-considerations)。
