2026-11-03，增量基线 `eae0b4a`。这是测试显示与记录入口，不向比赛发送定位，不改变正式配置/状态机。

当前版本已完成用户选择的雷达独立工作进程：桌面整链约10.08Hz扫描/199.65Hz Pose/48.23Hz速度API，丢包0。
几何算法与阈值保持，实车精度仍待验证。最新实现、对照和边界见 [性能交付记录](lidar_dynamic_performance_20261103.md)；下文早期延迟/USB记录为历史证据。

## 当前使用方式（自由初始化）

桌面：`雷达-T265动态定位.desktop`。当前启动前快速准备T265：运行态跳过复位、boot态直接加载固件，无固定5秒循环，再启动官方轮速输入和雷达链路。
本机冷启动0字节故障仍未恢复，不能把快速报错称为修复；见[T265 USB快速启动与实测](T265_USB_FAST_START_20261104.md)。
SDK、底盘UART各一个拥有者，雷达有独立工作进程。关闭其他T265/底盘调试窗口，启动时保持车静止；运动必须由用户点击。
USB恢复记录与定位数据保存在同一会话，供下次切换供电重启后验证，详见[T265 USB恢复](T265_USB_RECOVERY_20261104.md)。

1. 下一次建议放在场地中心附近无遮挡、平整处，避开出发区减速带。**无需精确摆在(0,0)，无需指定初始车头角度。**
   静止后点“静止后自动定位”；雷达估计位置和相对围栏航向，连续三帧一致后建立参考。
   地图原点仍是3m方形场地中心，+X向右、+Y向上、逆时针正。
   四个90°等价解中，选初始车头最接近+X/0°的一支，保留真实夹角。它不识别实际红蓝或场地四边身份。
   只有单墙或几何不足时显示等待，不把未知位置硬设为中心；后续转弯不会自动换90°分支。
2. 默认200mm/s、60°/s。前后左右均相对车身，每次单击执行50cm；转向按钮为±90°。
   **再次点击同一正在执行的动作会发送STOP**。700mm/s按钮只是切换参数，之后仍须再点动作按钮。
3. 过减速带/障碍物、围栏被遮挡时点“越障暂停雷达”；原始扫描继续记录，地图靠已有SDK Pose/主yaw传播，
   不更新墙面XY。回到平整且可见围栏的位置再点“恢复雷达修正”；恢复必须重新通过墙几何判定，不归零或自动换分支。
   这是人工标记，自动遮挡/倾斜识别尚未标定，不能把任意小残差都当成看到了围栏。
4. 动作结束、实物停稳后点“停稳后记点→录入实测”，格式 `前向mm,左向mm,转角deg`，未知填`?`，回车保存。
   DONE/进度/主yaw/T265返航不作独立真值。STOP按钮或空格/S停车；退出仅在本会话发过运动后请求STOP。

蓝线是安装外参修正并转换到当前初始化坐标系的T265中心轨迹（默认已依赖SDK轮速输入），橙线为雷达修正后结果。
红点是雷达点（半径2px、抗锯齿），人工禁用时显示灰点；场地边线减为1px、网格变浅。`Wall: x/y`为当前可观轴，`Wall: VIO`为未取得当前墙约束，`Wall: OFF`为人工暂停修正。
SDK区域区分OFF/WAIT_CFG/CFG_OK/API_OK，显示API成功数、频率和最近成功年龄；API_OK不等于设备融合增益或定位精度通过。
当前已加入用户选择的来源切换：正常显示“T265定位／轮反馈续推”，空间冲突后显示“降级：轮速＋主yaw”；
橙线为当前来源＋雷达修正，蓝线继续保留原T265，不相互替换。恢复需运动与双轴墙一致后平移重对齐，不以confidence升高自动切回。
具体阈值、离线回放与待验证内容见[T265_DYNAMIC_FALLBACK_20261104.md](T265_DYNAMIC_FALLBACK_20261104.md)。
FAULT会显示原始代码，例如`FAULT 3 ODOM`，不能直接解释成编码器损坏。

本次224334现场FAULT是下位机IMU短暂RECOVERING引起的Location无效，**更换上位机初始坐标不能修复它**。
证据和下位机配套任务见 `f405_fault_analysis_20261103.md`、`f405_fault_followup_20261103.md`。

桌面不动车检查仍复用原入口（不作为围栏精度验收）：

```bash
python3 localization/tools/lidar_t265_motion_map.py --sensor-check-seconds 10 --no-log-prune
```

此模式没有可点击窗口、不发运动；会尝试围栏初始化但不假设已知点位。没有完整Pose/主yaw/扫描则返回失败，原日志保存。
下文旧会话采用1号/135°的内容属于历史，不覆盖当前自由初始化。

## 实现与接口

- `lidar_t265_motion_map.py`继承原T265地图，复用F405客户端/动作协议、SDK生命周期、会话、M/G和原始记录。
- 同一个C++ SDK进程的测试专用 `--debug-pose-socket @...` 发出逐帧中心Pose；有界非阻塞SEQPACKET，记录累计丢包。
  采集/回调接收/桥接处理时间分开，SDK时钟到monotonic只记估计，资格不改true。
- 主yaw来自有效08原生累计角，优先MCU时钟映射，缺映射使用接收时间并注明；旧1F仅作未收到08时的兼容来源。
  围栏全局初始化确定当前场地航向后，建立主yaw固定偏置，不修改原gyro正方向。设备身份变化撤销参考，不自动恢复运动。
- `lidar_yaw_debug/dynamic.py`按原始点时刻插值/外推T265中心平移与主yaw：
  `p_ref = R_refᵀ (R_i (R_BL p_L + t_BL) + t_i - t_ref)`。
  外推跨度明确记录，时间未知不拒绝数据；不将外推标成实测时间/已标定去畸变。
- 墙面拟合只更新可观测的X或Y平移偏差，另一轴继承T265；固定yaw，不让墙拟合偷偷改变陀螺方向。
  其后T265继续传播位移，下一扫描再更新可观轴。扫描只读取未被自身修正的运动历史。
- 雷达倒装、145°定位/147°展示的安装记录、坏角屏蔽、原外参保留。当前绿色点显示的是实际用于拟合的145°子集。
  保留原补丁的关联/围栏/残差约束；没有把桌面物体强行匹配成3m围栏。
- 官方输入仍为 `R_CB(v_B + ω×r_BC)`，T265 SDK源T/W=0、sigma=0.10m/s；安装候选和比例1.000不变。
  不增加外部轮式位置加权。开启注入后，轮反馈和主gyro已经是T265输入依赖，不能再次当独立真值。
- 测试身份/状态/计数参考/DONE处理移除单纯年龄拒绝；真实动作deadline、CRC、模式、故障、SEQ/epoch归属仍检查。
  正式比赛其余旧时间门仍属TIME-01B，本次没有迁入比赛算法。

补丁审查来源：`雷达与融合/补丁/shijue_fangan_融合定位补丁_20261030/fusion_patch/`；
读取并核对deskew/fence/math/types，不运行apply_patch.sh，不套用默认配置、时间准入或STOP锁存。
文件来源及改动摘要见 `localization/tools/lidar_yaw_debug/PROVENANCE.json`。

## 2026-11-03复核：耗时构成与重插结果

用户已确认T265重插并保持静止；对批量抽点的答复是要求先解释耗时原因，**不是批准算法变更**。
本轮未修改运行代码、未合入候选抽样。

在同75帧原始扫描上，仅在内存中给原函数计时，无cProfile：每帧点数中位177，
69/75帧运行7轮（4帧6轮、2帧8轮），每轮160次choice，通常共1120次小型NumPy调用。
抽样阶段中位97.761ms，函数CPU中位124.541ms、墙钟125.173ms，墙钟P95 139.139ms；
总抽样时间占总函数时间78.0%。此前133ms是同量级离线结果，并非直线几何计算必需的开销。
当前算法是通用RANSAC＋TLS，未调用霍夫。逐轮移除支持点、继续搜索剩余点，即使最后仅保留1～2条线，也可能尝试7轮。
仅抽样的微基准：1600次choice约130.69ms；临时批量生成相同数量不重复点对约1.97ms，
后者改变随机序列，尚未合入。这不是完整定位耗时或精度结论。

### 自由初始化的必要检查

复用补丁global_init.initialize和localize，仅用于初始XY/航向估计；不加载其AutoLaser、nearest-corner策略或时间门。
8个理想射线场景（中心/非中心位置各4个90°方向）检查初始分支和XY，误差小于1mm/0.1°；
这些只是有真值的合成几何检查，不是雷达实车精度。另覆盖单墙不初始化、重复物理扫描不增加确认、
越障暂停不更新偏差、恢复后重新检查可观轴。
