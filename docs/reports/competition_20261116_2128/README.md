## 需要讨论的修复边界

原补丁只回答“物块是否在区内”，不足以回答“抓它时爪子会不会伸进安全区”。不能只降低黑框重叠阈值或扩大红/蓝框，把确实在入口外的漏送物块说成区内。

建议把三类区分开：已在区内的禁止选；离区足够远的沿原抓取；在入口附近、普通抓取所需前进会触到安全区的，不能直接按普通抓取冲过去。检查对象应包含张开爪尖与车体范围、有限段及后续mode21补进，不能只看车中心XY。双方安全区一致；只有己方正常投送及既定安全扫障可以使用其原授权路径，敌方安全区不开放投送。

视觉看清入口边界为主，既有定位/雷达场地位置辅助，不能只相信T265坐标；红蓝检测矩形的下边也不能未经核对就当精确实物入口边。仅当目标/轨迹靠近安全区又看不全时，复用抬头看全后再判，非每抓一次都加等待。所需爪子尺寸、画面边界到实际可走距离的换算应先核对，不拍脑袋指定禁入厘米数。目标锁定后、已有有限前进中和抓前自主补进中都要能实际取消；下位配合限制已授权段，不能仅由上位删候选框。

用户待决定：入口外的遗留物块先跳过（最快堵住本例、可能放弃可得分物块），还是后续设计专门处理（侧向抓回，或先按正规目的地半区对准再补推；空间、隔板接触和执行代价需要另审）。建议先堵普通抓取越界，不直接上线自动补推，也不擅自加全车FAULT。

## 分值权重提案，不是已实施

用户给定绿5/黑10/橙15，首绿保留；首件后现代码绿/黑/橙只按近远选。绿黑混运最多2件已有审核支持；橙仍单独运。权重必须后于安全区/危险/抓取合法性，不允许高分覆盖这些条件，也不能每帧重排已锁目标。

建议用一个统一的“预计本趟得分/预计本趟耗时”比较替代单纯最近，避免绝对橙优先导致远绕。耗时应包括抓取审核、接近、回安全区/对准放下；不是分数除以图像Y、框大小或仅接近距离。原距离估计存在米/分区/像素不同来源，像素不能冒充米计算价值。暂缺完整可信耗时标定，本轮不指定系数或宣称能稳定提高到50分。

不为“看起来是一堆”额外加奖励。只有确实能同趟运的组合才可考虑分值相加：双绿10、绿黑15、双黑20；橙与绿黑混堆不能把分数直接相加，远处半框更不能当易抓高分堆。建议先只让单目标参与分值选择，原抓到合法双件照旧运；可靠成对选取另议，避免恢复旧堆优先/远处半框优势。距近候选差不多用时，橙应优于绿；极远橙或须分离的混堆则要折算实际代价。抓取中遇到更高分不换锁；确认原目标丢失/完成/明确放弃后才重选。
