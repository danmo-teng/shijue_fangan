# 围栏前有框却不接近：脚点几何候选

仅候选分支，不部署原正式入口。原函数cargo_in_front_region把目标框中心或底心任一投影进安全区色框都排除，且又要求中心、底心同时在地面走廊内。对直立物体，物块上半身可投影覆盖安全区颜色，但实际接触位置仍在区外。

实际第二轮frame4502：mode42、蓝335置信0.85/hits8，bbox=(644,155,136,155)，safe_bbox=(352,4,926,245)。中心(712,232.5)在色框内，底心(712,310)在外；原函数False，候选True，原safe_sweep_target可选择335。录像及原始检测保留，不能把可选择等同成功夹到或清除。

候选改为只用底心判地面前区，显式inside_safe_zone、真实底心在安全区内/门槛、走廊外仍排除。它复用原走廊和载荷排除，不改YOLO/显示/ROI/任务协议，不增加计时、握手或等待。

两轮事件视频714个对象谓词对照：29个原排除→可入，无原可入→排除。第一轮14个（黑1/蓝4/橙9）、第二轮15个（蓝15）。独立核查关键真实图像符合围栏前地面物体；不是29次动作成功。其余仍须原选目标/类别/载荷身份条件。现有状态检查覆盖实际框、显式区内、底心在内/门槛、走廊外及原safe_sweep_target；原runner走廊/载荷/扫障拒绝相关检查通过。

取舍：底心只是单目框的接触点代理，遮挡、截断和色框边界不准仍可能误分；不承诺所有围栏场景准确。保原中心条件会漏掉已证蓝块；候选优先修这个真实误排除，而不通过改显示颜色掩盖。该几何修复不解决mode39逆迹卡住或mode42/43无目标无退出，需要单独审查。
