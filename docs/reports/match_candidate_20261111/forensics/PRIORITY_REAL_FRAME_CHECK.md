# 单橙优先：少量真实画面字段的反事实检查

只读离线调用，不是实车运行、整场重放或得分比较；未启相机/BPU/UART/SDK。原始日志不改。派生小JSON见priority_real_frame_check.json。

方法：从两轮事件片段的真实tracks、bbox/hits、相机角度、safe_bbox及blocked状态，调用当前candidate的make_vision_snapshot；距离字段由现有vision/config/approach_range.json生成，没有手填range_distances或虚构ground_xy。将first_common_delivered与first_green_visually_confirmed明确设为true，反事实表示首件已视觉确认。对同一快照调用ed07e32原_choose_next_batch方法和当前候选；其他快照几何共用当前候选，因此对比仅说明排序方法，不是全版本轨迹复现。

下面三帧来自第一轮20261111_140243_competition_wheel/safe_zone_replay_0001或0003；原状态都是RETURN_CENTER、mode17，不宣称当时程序实际会选新目标。它们证明正常live字段可以激活候选，不依赖仅测试时存在的米制ground_xy。

这些“mm”是用户既有按屏幕档保存的车体接近行程，不是本次独立测得的物体深度；同档不等于真实距离严格相等。橙176在2150是顶部截断远目标，候选仍不抢占更近材料；2193时同一橙已在画面中完整显露。未改变当前已锁目标，混载仍走原审核与分离，伤员仍只单件。

两轮事件片段中可比视图共有397个，排序不同41个；这是片段抽样对象，不能换算成41次动作或收益。这里只保留上述两正一负，不扩张成大套新测试。首件未视觉确认、距离未知、真区内排除与已锁目标边界已由现有针对检查覆盖。本项可证明候选可接通真实输入，不能证明路径更短、机械抓取成功、准确率或比赛分数更高。
