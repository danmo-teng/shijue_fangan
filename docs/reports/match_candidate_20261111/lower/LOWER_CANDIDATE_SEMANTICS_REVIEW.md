# 下位候选的独立源码复核（未实施）

参考：仓库 e85c738075451574e4c29ea7da05daf5a8258b6b。实跑设备自报 dirty1，因此这些仓库源码不能被称为与烧录字节完全一致。本文和三个补丁只供人及下位机负责人审阅，没有改对端仓库、构建固件、烧录或发电机指令。

## 39逆迹端点

`F405_REVERSE_ENDPOINT_CANDIDATE.patch` 的场地向量为 `-remaining*u - cross*n`，其中 `u` 是锁定段的正前向，`n=(-uy,ux)`。它与代码中的 `cross=-dx*uy+dy*ux` 一致；转为 `atan2(vy,vx)-当前主yaw` 后，现有 `Motor_MoveAngleHeading` 自己处理F405的前/左及轮系符号。越过终点平面后只消除超限横差，不继续倒车离终点更远，解决的是可严格构造的几何错误，不能据此宣称日志里39卡住的子相位已唯一确定。

该API是普通向量加减速及主yaw航向保持，**没有fine assist**。`APP_NAV_FINE_MIN_SPEED_MM_S` 在本次源码是 **110 mm/s**，故候选把原末端最小20提高到110，整体110–120；不是保留原速度，也不是复用STAGE的完整fine执行器。它可能缩短起动等待，也可能使贴障小距离横移更急，需要人审和短实测。保现有API比再扩一个FineHeading入口改动更小；目前不建议仅因静摩擦推测继续扩展motor接口。

`Motor_MoveAngleHeading` 的bool是命令接受，不是编码器证明已动；任务的motor_active位同样不能当运动真值。保留现有heading hold后不再外加另一套yaw输出，这一点正确。完成阈值、冻结段游标、转向与原流程均未改。若很早越过终点，旧完成条件原本就允许沿线超越后在横差合格时完成，候选没有另行证明实际回到精确端点。

`task_sweep_trace_begin` 的第一点为更早CLEAR时的safe_center，非当时实测XY。第二轮复算在此时已有约35mm差，尾段仍接近35mm；因此最后一段包含“回原中心”而非纯粹反走已测轨迹。板端Location是独立轮速+主yaw传播，不应与上位雷达/T265位置混淆。当前日志没提供reverse phase/cursor/consume_to，不能用这一个差值硬定根因。

## 42无目标及43真空爪的退出

`F405_SWEEP_SEARCH_COMPLETION_CANDIDATE.patch` 增加的仅是三个现有Task周期内的本地角度状态，只有新CLEAR业务清零，初次实际42采样才建立角度参考，排除此前39停车/转身；43回42及HOLD不清零。累计本趟取障周期的有符号跨0净角，往返纠偏不冒充完整一圈；只有进入搜索分支、没有有效目标且净角到±360度时结束本趟。它是物理转角预算，不证明相机无盲区；有效目标优先，不在追踪分支硬切断。

43只在原有两观测/STABLE机制已生成READY且NONEMPTY为假时调用原失败退路，不把缺图或placeholder当作空爪；没有新增timer、opcode、资格握手或数据年龄门。原缺证据3.5秒回42仍保留，但不再重置该趟净角预算；之后无目标且满圈可以退出。若持续拿到目标但爪内缺证据、净角又没到一圈，本候选不能宣称所有循环已消失。

失败原路是39开爪、逆迹回退、转回场地航向、**46**，上位已有46→RETURN_CENTER，下位也已有接收分支。**46不是45，也不是40成功**。它同样依赖39逆迹能够完成，且原载荷已寄存，失败退出会把原物资留在场上；不能称为找回或清障成功。更好的取回原货并换入口需要一致的结果语义/路线方案，本候选没有假造协议支持。

## 低速静摩擦机制的界限

`motor_zero_feedback_source_analysis.json` 直接调用本次仓库pid.c，假定单轮恒目标、反馈始终为零、PI不被复位，严格按100Hz演算。20 mm/s单轮命令的普通FF约106‰，理想输出5秒168‰、12秒249‰；110 mm/s则初始164‰、1秒227‰，到250‰约1.36秒。250‰只是假设比较值，**没有测得本车静摩擦阈值**，这些数值不是现场PWM回读，也不证明20秒开局停滞或39必是此因。三轮混合后并非每轮都达到车体向量速度。

START末段也走普通HeadingAPI；现有6个10ms制动周期不能解释20秒静止。`F405_START_HOLD_CONSISTENCY_CANDIDATE.patch` 只把legacy HOLD的WAIT_CONFIG/START/OPEN_CLAW豁免与现有runtime HOLD/PAUSE一致，不调整起步速度或任何到位阈值。legacy HOLD在START会Motor_Stop是源码中真实的潜在分支漏洞，但本两轮START没有被接受的HOLD证据，不能拿它当这次根因。不应通过放宽到位阈值到120mm、添加新超时、重复握手或永久FAULT掩盖实际未起动。
