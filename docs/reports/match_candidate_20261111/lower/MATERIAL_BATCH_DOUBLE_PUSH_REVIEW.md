# 既有首件阶段后的绿黑批量运输与双推：成对候选

## 行为与影响

- 保留现有首次审核：恰好单绿。沿用既有`first_delivery_done`阶段后允许1～3件绿/黑，同类或混合；伤员仍只单件；浅蓝危险、未知、伤员混合仍不合法。现有mixed_material=6和左右2-bit计数足够，不加协议字段、opcode或反复握手。
- 注意既有`first_delivery_done`也可能由视觉验证超时后TASK_COMPLETE推进，**不是首绿真实得分证据**。本候选保留两端兼容阶段，未暗加首绿证明门；“首件百分百视觉确认”的完整合同仍待另行决策。
- 两侧/总数仍必须匹配，mixed侧至少2件；原审核STABLE/两视角流程保持。合法批量直接走已有GRAB，无需先强分成单件。原核心物资50mm靠近机制保持。
- 是否双推只取本趟最后合法运输审核：首次ENTER锁存`audit_last_total_count`。3件寄存后只找回1件时按真实1件继续，不等待凑3，也不沿旧`sweep_original_total=3`双推；找回2件才走2件双推。

## 机械顺序

第一次仍是原ENTER/安全区推进。批量>=2时，在mode12内部执行：

1. 沿原退出顺序，左右爪打开，S1到55；
2. 保第一次ENTER锁存航向，后退300mm，速度400mm/s；
3. S1到86，前进300mm，速度330mm/s；
4. S1到55，再后退300mm，速度400mm/s；
5. 以上真实内部距离动作完成才发布15，沿原视觉验证/TASK_COMPLETE；16只恢复S1到86，不额外第三次后退。

航向保存在专用`delivery_push_heading_deg`，复制首次ENTER的`nav_locked_heading_deg`。这样进入12/15时通用task_enter清零nav字段，不会把二推误改成0°。普通单件/单伤员/开局藏物路径保持原行为。重复ENTER仍是原接收分支ACK，不会重新启动双推；PAUSE/HOLD沿原框架暂停，局部路径起点保存，半程恢复只走剩余距离。STOP仍走原REMOTE_STOP/恢复流程，不承诺保留本双推phase续跑。S1可能在PAUSE期间继续运动，角度等待不是真舵机反馈。

55/86这里只能按原退出“55→退→86”的源码顺序复用，**没有独立证明实物上下**。S1每次使用已有`Lift_PositionWaitMs`按指令角估算的行程时间，31°约101ms，不是真舵机反馈，也没有新增固定等待常量。300mm/400及330均复用现有退出距离/速度和终推速度；其第二推效果、打滑及三件实际入区仍需实车确认，不能由轮进度自证。
