# 正式运输导航已停车恢复

本次仅修改上位机，不改夹内审核或下位机协议。

在正式 NAVIGATE 中，定位与STM状态新鲜、无故障、当前NAV上下文已接受、mode10合爪、电机未运行、DISTANCE_DONE未置位，且尚未到预备点容差、未进入STAGE D=0握手时，独立观察停车无进展。连续3秒未出现现有阈值规定的位置或航向变化，触发既有ESCAPE_MANEUVER。SEQ/ACK刷新和轮子空转不算这条分支的位置进展；状态或观察中断后重新计时。

该分支不受原来距目标30 cm内跳过运动堵转检查的限制，不扩大到开局藏堆、抓取审核、投送退出或返中阶段。原有电机运行中的堵转逻辑保留。

流程：NAVIGATE → FIELD_STUCK_ESCAPE → 本次上下文的新鲜mode31 → 按当前定位重新计算STAGE NAV → 到预备点后按原流程mode48复审。

脱困完成不能只凭ACK。恢复时清除旧到达/ALIGN锁存和堵转计时，保留批次、携带清单、目的地、任务归属和首件/投送计数。现有发送器在NAV→ESCAPE→NAV命令切换时分别分配动作编号，同一动作重复发送及H/D更新不更换编号。

当前核对的F407 d3913f4已支持NAV接受ESCAPE、完成mode31、完成后接受NAV并重新建立导航段，因此本次不需要下位机修改。需实机固件具备该既有链路；未新增命令或状态。持续受阻时不承诺一定脱困，本改动解决的是导航主动停车后缺少上位机恢复出口。
