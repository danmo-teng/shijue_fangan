## 实现修正和接口

- `f405_test_client.py`：唯一UART owner继续混合解析旧/新协议，显式请求时先身份核对、
  发送带nonce的SYNC，建立因果候选映射，再配置07/08。请求和回执按type/seq/nonce/boot/时限匹配；
  主机接收事件不是源采集时刻，只有收到事务不是时间资格。
- `f405_timed_measurements.py`：真实forward/left μm/s→m/s，按原始delta和实际t0/t1复核新F405运动学；
  gyro mdps→deg/s→相同轮区间的平均rad/s。源ID去重/回绕，异常/重复/缺包不制造零值。
  MCU漂移与采样不确定度未知时保持null/false；当前固件不能进入合格输入。
- `t265_wheel_input.py`：有界后台队列和独立worker，GUI只取快照/提供主机动作上下文。
  gyro完整覆盖同一轮区间后积分，保持20ms最大gyro间隔、5ms不确定度、50ms年龄预算。
  只生成一次`v_C^C=R_CB*(v_B^B+omega×r_BC^B)`；不做外部位姿积分/加权融合。
- `async_debug_log.py`：串口/转换线程不写盘、不JSON序列化；有界日志后台写入。
  溢出/写盘失败明确记录、会话不完整且不允许无记录注入，不丢弃后假称完整，也不锁存底盘永久故障。
- `debug_wheel_input.cpp`：同一SDK对象，启动前加载零T/W、I轴向配置；SDK输入worker与Pose轮询/GUI/磁盘分离。
  再检查年龄、顺序、单位、外参、epoch，真实调用send_wheel_odometry并记录返回。
  native日志后台写盘，状态提供配置加载、真实API成功数、近1s接受频率、最近成功时间及日志完整性。
- `main.cpp`：debug会话使用原pipeline的独立Pose回调队列，保留真实回调接收时刻、
  SDK采集时刻、frame_number、完整姿态/速度/confidence和队列丢弃数；正式默认路径不变。
  A/B各有SDK进程PID、session_id、序列号、固件和实际stream profiles，不伪造设备boot epoch。
- 原地图明确四状态：未请求、已请求但受阻、SDK已加载配置、存在实际SDK API成功样本。
  IPC成功不算API成功，API成功也不是设备内部融合确认或地面精度。显示频率、成功年龄、拒绝原因、输入年龄。
  原始相机中心投影、C→B车中心、依赖T265航向的轮反馈参考分别标注。

当前候选仍为r_BC=(-0.0346105,-0.0599471445,0)m、forward_C=(0.8660254,0,0.5)、up_C=(0,-1,0)。
SDK输入外参T=W=0，不重复轴变换、杆臂或内部IMU偏置。噪声标准差0.10m/s仍为工程初值，未调小。
SDK frame_num为源序号，不是时间戳，reference重设不重置它。
实际有API成功或API失败后可能影响估计器的wheel/gyro依赖会保留，停发不会立即清除。

## 针对性A/B和图像证据操作

时间质量尚缺时，不跑一个“0接受”的B去比较精度。先由下位机补实测误差界并审核，再按相同安装、固件、
路径及stream profile独立开SDK会话；必要时由用户实际重启设备并记录，程序不强制硬重启。
debug-fresh-session关闭map preservation不等于内部状态已彻底清空；停止发送不等于去除了轮速影响。

```bash
# A：原入口，未请求注入；可订阅测量以保证A/B的UART负载一致
localization/tools/desktop_launcher.sh --baud 230400 --chassis-profile timed --wheel-input off --timed-measurements --no-log-prune
# B：先退出A、建立独立实际SDK/设备会话，再开；必须看到API成功数持续增长才算有效B
localization/tools/desktop_launcher.sh --baud 230400 --chassis-profile timed --wheel-input on --no-log-prune
```

每段只由用户主动触发：前进1m→转180°→前进1m→倒退1m，再一次原地360°。
独立卷尺/地面线确认距离、方向和中心是否横移；物理停稳后M冻结，再G录入。
标称值、DONE、同一gyro及T265生成的返程距离都不是真值。缺少实测时不出比例校准。

需要看转180°前后两鱼眼时，原入口增加`--fisheye-evidence`，在相关动作前后按C。
同一SDK进程/设备/pipeline导出两鱼眼；每次最多2秒、4对/秒，每会话最多2次，最多32张PGM。
后台写PGM与fisheye_frames.csv，包含实际SDK帧号/采集时刻/时间域/接收时刻与丢弃数。
默认不启用；启用会增加USB/处理负载，定量A/B须保持同一profile并查看实测Pose频率和缺口。
本轮只编译核查该选项，未采集转动时画面，不能据此确诊遮挡或特征问题。
只清理由本会话manifest明确登记的图片，用户添加/改动为未知文件时保护整个目录。
