# 四出发区 / 红蓝方救援地图

该目录在 RDK X5 桌面运行统一启动窗口，启动时选择1–4号出发区、红/蓝方和定位方式。
点击“确认并开始”后，它会同时启动定位与YOLO识别窗口，并在赛题图6的3 m × 3 m场地上显示：

- 小车实时位置和车头方向；
- 融合轨迹和累计行驶距离；
- T265 tracker/mapper 置信度；
- 编码器 UART 新鲜度和轮速门控状态；
- 本方安全区、四个出发区和减速带。

地图与视觉使用独立窗口，可在RDK桌面用`Alt+Tab`切换；关闭地图或返回重选时，由地图启动的
识别和定位子进程会一并停止。
窗口画布按 RDK X5 的 `1280×1024` 桌面设计，场地始终保持正方形等比例显示，不通过裁剪来填满屏幕。

## 坐标和八种开局

坐标原点位于场地中心，`+X` 向图纸右，`+Y` 向上，角度从 `+X` 逆时针增加。赛题图中的 1/2/3/4 号区依次为左上、右上、左下、右下。

按当前方案，小车定位参考点到对应场地最外角的直线距离为 300 mm。由于小车位于角点的45°对角线上，X/Y方向的偏移各为 `300 / √2 ≈ 212.1 mm`，因此默认初始坐标为：

| 出发区 | 初始 X | 初始 Y | 车头方向 |
|---|---:|---:|---:|
| 1 左上 | -1.288 m | +1.288 m | 135° |
| 2 右上 | +1.288 m | +1.288 m | 45° |
| 3 左下 | -1.288 m | -1.288 m | 225° |
| 4 右下 | +1.288 m | -1.288 m | 315° |

四个方向均让车头朝向外角，机器人以倒车方式越过出发区障碍进入场内。红蓝方只决定本方安全区：红方在上边中央，蓝方在下边中央；不改变出发位姿。

本车T265固定安装后，旧地图轨迹比实际行驶方向逆时针偏90°。运行配置使用`camera_to_robot_yaw_deg=-90.0`，在投影到地图前把T265平面位移和速度顺时针校正90°；初始车头方向和T265相对转角不额外偏移。

这里的“距外角 300 mm”指机器人定位参考点（通常配置为底盘旋转中心）到场地角点的直线距离，不是分别距两条外边界300 mm。如果现场摆车基准指的是车体边缘而不是旋转中心，应测量后通过 `--corner-offset-mm` 修正，不能把外壳尺寸直接当作定位原点。

## 正式运行

确认 `/dev/ttyS1` 已接好 F407、T265 正常连接后：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/rescue_map
./run_rescue_map.sh
```

地图仍实时显示本机融合位置，但默认`--tx-rate 0`，不再向F407连续发送`TYPE=0x16`，避免串口
持续位姿流影响任务命令。F407的行驶输入改为任务程序计算的航向和定距。

运行依赖 Python 3、OpenCV、NumPy、Pillow，以及已经编译好的 `localization/build/t265_omni_localizer`。启动脚本会先检查这些依赖和 UART 权限。

## 启动定位方式与初始位置

启动页除出发区和红蓝方外，还可以选择：

- `T265+编码器`：默认模式；打开`/dev/ttyS1`，融合T265与F407三轮编码器。
- `仅T265`：不打开UART、不读取编码器，也不向STM32发送数据；用于核对T265初始位置、方向和地图坐标。

选择`T265+编码器`时启动完整`mission_test`识别/任务窗口，YOLO结果通过定位进程转发给STM32；
选择`仅T265`时只启动独立YOLO识别窗口，不发送STM32任务命令。

“距角落顶点”是机器人定位参考点到对应场地角点的直线距离。可在启动页用`−50 / −10 / +10 / +50`按钮调整；快捷键`- / +`每次调整10 mm，`[ / ]`每次调整50 mm。默认300 mm。

命令行也可直接指定，便于重复调试：

```bash
# 仅T265，初始位置距所选角落300 mm
./run_rescue_map.sh --localization-mode t265 --corner-offset-mm 300

# 启用T265+编码器融合，初始位置距所选角落450 mm
./run_rescue_map.sh --localization-mode fusion --corner-offset-mm 450
```

启动页可鼠标点击，也可使用：

- `1`–`4`：选择出发区；
- `R` / `B`：选择红方 / 蓝方；
- `E`：在`T265+编码器`与`仅T265`间切换；
- `-` / `+`：距角落顶点减小/增大10 mm；`[` / `]`：减小/增大50 mm；
- `Enter`：保存选择并同时启动定位与识别；
- 运行中 `S`：停止识别和定位并返回选择页；
- 运行中 `R`：清空显示轨迹和累计距离，不改变融合定位原点；
- `F`：切换全屏；
- `Q` / `Esc`：退出并停止由本界面启动的定位进程。

若实际定位参考点距外角为 150 mm，可这样运行：

```bash
./run_rescue_map.sh --corner-offset-mm 150
```

## 运行文件

确认开局后自动生成以下文件，它们不会提交到 Git：

- `runtime/session.json`：本次出发区、红蓝方和初始位姿；
- `runtime/localization.conf`：传给融合定位程序的配置；
- `runtime/localization_result.json`：T265+编码器融合实时输出。
- `runtime/uart_command.bin`：任务程序交给定位进程转发的15字节UART帧；
- `runtime/stm32_status.json`：STM32爪子、摄像头和任务状态。
- `runtime/delivery_contact_pose.json`：投送完成时的观测位姿、围栏相切参考位姿及建议位置偏差；仅供标定分析，不会自动重置融合定位。

地图程序不会直接解释原始编码器帧，而是复用 `localization` 中已经测试过的 UART 协议、三轮全向运动学、减速带门控和 EKF。这能保证屏幕显示位置与回传给 F407 的融合位置使用同一套坐标。

融合 JSON 超过 250 ms 没有更新时，界面会显示 `STALE`；文件缺失或无法解析时显示 `NO_DATA`，并停止累加轨迹。定位点发生大于 350 mm 的单帧跳变时不会计入距离，避免 T265 丢失后的跳点污染路线。
