# 四出发区 / 红蓝方救援地图

该目录在 RDK X5 桌面运行统一启动窗口，启动时选择1–4号出发区、红/蓝方和定位方式。
点击“确认并开始”后，它会同时启动定位与YOLO识别窗口，并在赛题图6的3 m × 3 m场地上显示：

- 小车实时位置和车头方向；
- 融合轨迹和累计行驶距离；
- T265 tracker/mapper 置信度；
- 编码器 UART 新鲜度和轮速门控状态；
- 本方安全区、四个出发区和减速带。

地图车体圆使用130 mm碰撞半径；105 mm推板接触偏置和150 mm前拨板偏置属于机构参数，不能
替代地图车体半径或分区中心坐标。

地图与视觉使用独立窗口，可在RDK桌面用`Alt+Tab`切换；关闭地图或返回重选时，由地图启动的
识别和定位子进程会一并停止。
窗口画布按 RDK X5 的 `1280×1024` 桌面设计，场地始终保持正方形等比例显示，不通过裁剪来填满屏幕。

## 坐标和八种开局

坐标原点位于场地中心，`+X` 向图纸右，`+Y` 向上，角度从 `+X` 逆时针增加。赛题图中的 1/2/3/4 号区依次为左上、右上、左下、右下。

出发区为300×300 mm，小车中心位于出发区中心，因此X/Y坐标固定为±1350 mm。若用到角点的径向距离表达，同一个位置对应`150×√2≈212.132 mm`，不是300 mm。

| 出发区 | 初始 X | 初始 Y | 车头方向 |
|---|---:|---:|---:|
| 1 左上 | -1.350 m | +1.350 m | 135° |
| 2 右上 | +1.350 m | +1.350 m | 45° |
| 3 左下 | -1.350 m | -1.350 m | 225° |
| 4 右下 | +1.350 m | -1.350 m | 315° |

四个方向均让车头朝向外角，机器人以倒车方式越过出发区障碍进入场内。红蓝方只决定本方安全区：红方在上边中央，蓝方在下边中央；不改变出发位姿。

T265镜头朝上安装后不再提取绕Y欧拉角，也不使用固定二维yaw补偿。配置中的轴向向量表示
“机器人轴在T265 Pose本体坐标中的坐标”。实车校准后为前向`+X`、上向`-Z`，左向由
`up×forward`得到`-Y`。这会只翻转地图左右方向，不改变已经校准正确的前后方向。T265
Pose坐标与图中标出的IMU子坐标方向不同，配置使用的是Pose坐标。

正式任务启动时会把第一帧有效融合位姿与所选理论点比较；平面误差超过20 mm时输出
`START_POSE_MISMATCH`并禁止发送赛前配置命令。

## 正式运行

确认 `/dev/ttyS1` 已接好 F407、T265 正常连接后：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/rescue_map
./run_rescue_map.sh
```

也可以直接双击桌面上的“智能救援一键启动”。首次部署或桌面图标丢失时执行：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/rescue_map
./install_desktop_launcher.sh
```

桌面入口调用`desktop_launcher.sh`，后者再调用同一个`run_rescue_map.sh`，因此命令行和双击运行
使用完全相同的地图、定位、识别与串口参数；启动失败时终端不会立即消失。

地图仍实时显示本机融合位置，但默认`--tx-rate 0`，不再向F407连续发送`TYPE=0x16`，避免串口
持续位姿坐标流影响任务命令。F407的行驶输入改为任务程序根据本机融合位置持续计算的航向和剩余距离。

运行依赖 Python 3、OpenCV、NumPy、Pillow，以及已经编译好的 `localization/build/t265_omni_localizer`。启动脚本会先检查这些依赖和 UART 权限。

## 启动定位方式与初始位置

启动页除出发区和红蓝方外，还可以选择：

- `T265+编码器`：默认模式；打开`/dev/ttyS1`，融合T265与F407三轮编码器。
- `仅T265`：仍打开UART、发送赛前配置和完整任务命令，但通过`--ignore-encoders`禁止编码器进入定位融合，地图位置只使用T265。因此该模式也能正常出发、识别和搬运。

两种模式都会启动完整`mission_test`识别/任务窗口，YOLO结果和任务命令通过定位进程转发给
STM32；区别仅在于编码器是否进入融合计算。

任务命令转发线程独立于T265取帧：短暂定位停帧时仍以100 Hz维持当前`TYPE=0x18`命令；视觉
命令文件超过250 ms不更新后停止代发，由下位机看门狗停车。

“距角落顶点”是机器人定位参考点到对应场地角点的径向距离，默认212.132 mm，对应
`start_center_m=1.350`。正式任务不应修改该值，否则20 mm启动校验会拒绝启动。

命令行也可直接指定，便于重复调试：

```bash
# 仅T265，使用出发区中心
./run_rescue_map.sh --localization-mode t265 --corner-offset-mm 212.132

# 启用T265+编码器融合，使用同一出发区中心
./run_rescue_map.sh --localization-mode fusion --corner-offset-mm 212.132
```

启动页可鼠标点击，也可使用：

- `1`–`4`：选择出发区；
- `R` / `B`：选择红方 / 蓝方；
- `E`：在`T265+编码器`与`仅T265`间切换；
- `-` / `+`：距角落顶点减小/增大10 mm；`[` / `]`：减小/增大50 mm；
- `Enter`：保存选择并同时启动定位与识别；
- 运行中 `S`：停止识别和定位并返回选择页；
- 运行中 `R`：清空显示轨迹和累计距离，不改变融合定位原点；
- `F`：切换全屏；
- `Q` / `Esc`：退出并停止由本界面启动的定位进程。

## 运行文件

确认开局后自动生成以下文件，它们不会提交到 Git：

- `runtime/session.json`：本次出发区、红蓝方和初始位姿；
- `runtime/localization.conf`：传给融合定位程序的配置；
- `runtime/localization_result.json`：T265+编码器融合实时输出。
- `runtime/uart_command.bin`：任务程序交给定位进程转发的15字节UART帧；
- `runtime/stm32_status.json`：STM32爪子、摄像头和任务状态。
- `runtime/delivery_contact_pose.json`：投送完成时的观测位姿、围栏相切参考位姿及建议位置偏差；仅供标定分析，不会自动重置融合定位。
- `runtime/mission_diagnostics.json`：50 Hz任务状态、STM32模式/故障/ACK、最后命令、规划位姿、航向、剩余距离和串口帧龄。

地图程序不会直接解释原始编码器帧，而是复用 `localization` 中已经测试过的 UART 协议、三轮全向运动学、减速带门控和 EKF。这能保证屏幕显示位置与回传给 F407 的融合位置使用同一套坐标。

融合 JSON 超过 250 ms 没有更新时，界面会显示 `STALE`；文件缺失或无法解析时显示 `NO_DATA`，并停止累加轨迹。定位点发生大于 350 mm 的单帧跳变时不会计入距离，避免 T265 丢失后的跳点污染路线。
