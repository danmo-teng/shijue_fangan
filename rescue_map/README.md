# 四出发区 / 红蓝方救援地图

该目录在 RDK X5 桌面运行一个独立窗口，启动时选择 1–4 号出发区和红/蓝方，共覆盖 8 种开局。确认后它启动现有 `localization` 程序，读取 T265 与 F407 三路编码器的融合位姿，在赛题图 6 的 3 m × 3 m 场地上显示：

- 小车实时位置和车头方向；
- 融合轨迹和累计行驶距离；
- T265 tracker/mapper 置信度；
- 编码器 UART 新鲜度和轮速门控状态；
- 本方安全区、四个出发区和减速带。

它与视觉识别窗口完全独立，可以在 RDK 桌面后台切换。
窗口画布按 RDK X5 的 `1280×1024` 桌面设计，场地始终保持正方形等比例显示，不通过裁剪来填满屏幕。

## 坐标和八种开局

坐标原点位于场地中心，`+X` 向图纸右，`+Y` 向上，角度从 `+X` 逆时针增加。赛题图中的 1/2/3/4 号区依次为左上、右上、左下、右下。

按当前方案，小车定位参考点距对应场地最外角 300 mm，因此默认初始坐标为：

| 出发区 | 初始 X | 初始 Y | 车头方向 |
|---|---:|---:|---:|
| 1 左上 | -1.20 m | +1.20 m | 135° |
| 2 右上 | +1.20 m | +1.20 m | 45° |
| 3 左下 | -1.20 m | -1.20 m | 225° |
| 4 右下 | +1.20 m | -1.20 m | 315° |

四个方向均让车头朝向外角，机器人以倒车方式越过出发区障碍进入场内。红蓝方只决定本方安全区：红方在上边中央，蓝方在下边中央；不改变出发位姿。

本车T265固定安装后，旧地图轨迹比实际行驶方向逆时针偏90°。运行配置使用`camera_to_robot_yaw_deg=-90.0`，在投影到地图前把T265平面位移和速度顺时针校正90°；初始车头方向和T265相对转角不额外偏移。

这里的“距外角 300 mm”指机器人定位参考点（通常配置为底盘旋转中心）相对两条外边界的 X/Y 距离均为 300 mm。如果现场摆车基准指的是车体边缘而不是旋转中心，应测量后通过 `--corner-offset-mm` 修正，不能把外壳尺寸直接当作定位原点。

## 正式运行

确认 `/dev/ttyS1` 已接好 F407、T265 正常连接后：

```bash
cd /home/sunrise/RDK_X5/shijue_fangan/rescue_map
./run_rescue_map.sh
```

运行依赖 Python 3、OpenCV、NumPy、Pillow，以及已经编译好的 `localization/build/t265_omni_localizer`。启动脚本会先检查这些依赖和 UART 权限。

启动页可鼠标点击，也可使用：

- `1`–`4`：选择出发区；
- `R` / `B`：选择红方 / 蓝方；
- `Enter`：保存选择并启动融合定位；
- 运行中 `S`：返回选择页并重启定位；
- 运行中 `R`：清空显示轨迹和累计距离，不改变融合定位原点；
- `F`：切换全屏；
- `Q` / `Esc`：退出并停止由本界面启动的定位进程。

若实际定位参考点距外角为 150 mm，可这样运行：

```bash
./run_rescue_map.sh --corner-offset-mm 150
```

## 运行文件

确认开局后自动生成以下文件，它们不会提交到 Git：

- `runtime/session.json`：本次出发区、红蓝方和初始位姿；
- `runtime/localization.conf`：传给融合定位程序的配置；
- `runtime/localization_result.json`：T265+编码器融合实时输出。
- `runtime/uart_command.bin`：任务程序交给定位进程转发的15字节UART帧；
- `runtime/stm32_status.json`：STM32爪子、摄像头和任务状态。

地图程序不会直接解释原始编码器帧，而是复用 `localization` 中已经测试过的 UART 协议、三轮全向运动学、减速带门控和 EKF。这能保证屏幕显示位置与回传给 F407 的融合位置使用同一套坐标。

融合 JSON 超过 250 ms 没有更新时，界面会显示 `STALE`；文件缺失或无法解析时显示 `NO_DATA`，并停止累加轨迹。定位点发生大于 350 mm 的单帧跳变时不会计入距离，避免 T265 丢失后的跳点污染路线。
